# 候选竞技场

对同一任务扇出 N 个并行尝试。逐字读完每个候选。选出最强者作为基础（base）。把其他候选中最好的想法嫁接进基础。验证综合后的结果。

## 开始

派发任何东西之前，按阶段开一份 todolist，每阶段一条。arena 自治运行，这份清单防止阶段被悄悄跳过。

1. 定框
2. 扇出
3. 交叉评审
4. 选定
5. 嫁接
6. 验证

## 阶段 A：定框

N 个候选收到的是同一份提示，所以提示就是契约。派发任何东西之前把它写对。

1. 陈述每个候选要产出的产物。
2. 推导评分标准（rubric）。先陈述对这个具体任务而言成功长什么样，再把它转成 3-6 条可判分的具体标准。具体：`增加一个跳过写操作的 --dry-run 标志`。模糊：`代码是正确的`。rubric 是阶段 D 挑选者的工具；候选只看到任务本身。
3. 选定 runners。使用用户配置的 arena runners；未配置时，在用户可用的不同模型上各开一个（仅单模型可用时按委派纪律降级并记录）。当 arena 要覆盖多个设计方向时，增加 runner 数量。当工作是生成受限而非判断敏感时，同一模型跑 N 次也可以。
4. 分配输出路径。每个候选写到自己的位置（尽量用 git worktree，否则用系统临时目录下 `arena-<slug>/candidate-<n>/`）。N 个候选写同一路径就是共享可变状态，违反 nimo-principle-separate-before-serializing-shared-state。

## 阶段 B：扇出

用宿主提供的并行或后台子 Agent 机制，一次性派发全部 N 个 runner，每个带任务、共享锚定资料的路径、自己的输出路径，以及"同时产出产物和简短理由"的指示。宿主不支持并行后台子 Agent 时，按委派纪律串行独立执行并记录降级，保持候选互相不可见。

理由是强制的。没有理由，父 Agent 就无法判断候选的结构是出于原则还是出于偶然，阶段 E 的嫁接也就不可靠。每个理由要点名该候选考虑过哪些备选、拒绝了什么。

有候选没有产出时，以 N-1 继续推进，并在综合记录里记下退出者。

## 阶段 C：交叉评审

全部阶段 B 候选完成后，从用户配置的 arena 交叉评审池里选一个模型；未配置时使用用户可用的模型（仅单模型可用时按委派纪律降级并记录）。优先选与父 Agent 不同的模型家族。在该模型上派发一个只读评审子 Agent。它看到 rubric 和按路径标签标识的各个候选，对每条标准打分，并附理由推荐一个基础。它与父 Agent 在阶段 D 的阅读并行运行，而不是与候选本身并行。候选还在写时就派发评审，意味着评审看到的是部分或空输出，并把它们报告成退出者。

## 阶段 D：选定基础

选定之前，逐字读完每个候选。粗略翻完 N 个候选，只会挑出表面看起来最眼熟的那个。

逐条标准、而不是凭整体感觉，把每个候选对着 rubric 打分。与交叉评审的结果比较。对基础选择一致，确认这次选定；不一致，说明你们之一有偏差，或者 rubric 本身有歧义。决定之前先读两边的理由。

按"未来维护者最容易在不破坏不变量的前提下扩展"这个标准选基础。两个候选难分高下时，优先更干净的边界或更小的表面，见 nimo-principle-laziness-protocol。

在基础产物旁边记录一份简短的综合注记，包含选定结果与原因，以及交叉评审的判定。

## 阶段 E：嫁接

把每个落选候选再走一遍，识别值得移植进基础的东西。信号通常是每个候选一两处，不是大部分。

按 nimo-principle-redesign-from-first-principles，逐处手工折叠嫁接。不要机械粘贴。结果必须仍在一个心智模型下保持连贯。

记录嫁接了什么、来自哪个候选、拒绝了什么、为什么。拒绝注记是整份记录里信号最高的部分。未来的读者从你考虑过又丢弃的东西里学到最多，而不只是从保留的东西里。

当 N 个候选收敛到同一形状，这是强一致信号。在记录中注明收敛，直接交付共识形状，无需嫁接。当 N 个候选剧烈分歧，说明阶段 A 欠规格。重新定框、重跑，而不是把分歧平均掉。

## 阶段 F：验证

综合产物必须和其他任何输出一样经得起同样的审视，见 nimo-principle-prove-it-works。arena 不提供豁免。

如果验证暴露出 arena 没抓到的问题，要么阶段 A 错了（重新定框、重跑），要么某个候选抓到了而你在嫁接时漏掉了（回到阶段 E）。不要粉饰过去。

## 输出

一个综合产物。旁边一份简短的综合注记：基础是谁、嫁接了什么（带来源候选）、拒绝了什么、退出者（如有）、验证结果。

## 边界与交付

遵守 [宿主合同](../nimo-mode/references/host-contract.md) 和 [委派纪律](../nimo-mode/references/delegation.md)。只读、方案或停止要求优先，步骤不扩大授权。交付具体产物、当前版本证据、未完成项及原因。跳过保留理由，不能用 Skill 名称列表代替成果。
