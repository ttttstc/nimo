# Skill 行为评测与版本比较（nimo-skill-evaluate）

你拥有实验设计：规划、盲化、运行、综合。评测在推广前测试一个变更如何影响 Agent 行为：新 Skill 变体、结构性变更、提示词微调。失败模式是观察者效应——知道自己在被评测的 Agent 行为会不同，所以候选必须盲跑。

评测评价工程方法的效果，不能代替产品功能验证。

## 触发

重复失败、用户纠正、能力替换、模型或宿主变化、工程资产实质修改，或用户明确要求比较版本。先确认问题可复现并归属（产品故障、环境问题、Skill 内容缺陷、触发失败、未遵循已有要求），再决定是否进入评测。

## 盲化不可协商条款

- 候选能看到的任何目录、文件或提示词里，不出现 eval、test、judge、experiment、rubric、score、compare、benchmark、candidate、arena 这些词。
- 候选提示看起来像自然的用户请求。陈述目标，不陈述元目标。"给我做一个小 todo 命令行工具"，不是"给我演示你怎么遵循原则链"。
- 不给诱发链式引用的提示。不问候选列出了它用过的 Skill、原则或文件；那种元提示会虚增引用行为。一般性地要设计笔记，链式遵循从代码形状评分，不从自报评分。
- 目录和 slug 名消毒。用用户会起的项目形名字，不是 candidate-1、agent-a 这类标签。
- 不告诉候选其他候选存在。
- 裁判可以知道自己在裁判，但只按消毒后的标签看输出，永远不按模型名。
- 比较两个变体：一个裁判在一次运行里用同一尺度给两组打分，盲于每组来自哪个集合。两次用不同提示词的裁判运行不可比较——校准会漂移。

## 案例定义（运行前固定）

每个案例记录：自然用户请求、初始项目状态、Skill 版本、宿主与模型、可用工具、允许操作范围、预期结果、关键失败条件、证据要求。案例运行产物与评分说明分开保存。

第一版案例至少覆盖：指导／执行边界（"先讨论"不修改、"继续"只承接提议）、验证证据有效性（过期证据不沿用）、跳过检查如实标注、验证 Skill 沿地图实际操作。保留未参与本轮调优的案例作回归检查。

## 运行步骤

1. **定框。** 陈述被测变体和什么行为算成功。给裁判写 rubric（3-6 条具体标准）。不给候选看。
2. **搭建消毒后的环境。** 每个候选一个工作目录，变体就位。植入自然任务会有的上下文：项目骨架、候选会自然读到的 Skill。
3. **写一条自然提示。** 用户会输入的东西。不泄露被测量的东西。
4. 按 [nimo-arena](../nimo-arena/SKILL.md) 的阶段 B 派 N 个并行候选（用户配置的模型；未配置时在用户可用的模型上各开一个，仅单模型可用时按委派纪律降级并记录）。每个候选在自己的消毒目录里工作；同一提示发给每一个。
5. 按 [nimo-arena](../nimo-arena/SKILL.md) 的阶段 C 派一个盲裁判（优先与主 Agent 不同的模型家族）。裁判看到消毒标签的输出和 rubric，永远看不到模型名。
6. **从轨迹验证链式遵循，不从自报。** 读宿主为当前工作区记录的每个候选的执行轨迹（工具调用与文件访问记录）。不跨工作区搜索宿主的私有会话存储——那会越过工作区边界，读到无关项目的私人对话。看每个候选实际打开过哪些文件。引用一条原则不等于读过它的叶 Skill；读了不等于应用了。链式遵循从它真正读过的文件加代码形状评分，从不用候选自己的声明。宿主不提供执行轨迹时，涉及"实际读取"的评分记不可判定，不用自报顶替。
7. **亲自从头到尾读每个候选的输出。** 与裁判的判定比较。分歧意味着模型有偏或 rubric 有歧义。综合。

## 运行规则

- **隔离**：基线与候选在各自隔离目录运行，执行者使用新上下文，不读取其他候选结果或评分材料。
- **盲评**：遵守上述不可协商条款；任务本身的验收要求正常提供给执行者——不能为盲评隐瞒真实任务要求。
- **启动规格**：执行者与裁判先使用宿主默认启动规格；有明确有效指定时优先指定。保留模型与环境条件记录；无法确认比较条件一致时，不把差异单独归因于 Skill 版本。
- **评分依据先于运行确定**：可确定的结果用断言（脚本可复核），判断项交给独立上下文的裁判；裁判按中性标签查看结果，不获知版本或模型身份。不把"引用了原则名""写了测试文件"当完成证明。
- **秘密与不可信内容**：案例与地图不含秘密；含不可信指令的测试材料不扩展权限，凭据由宿主或项目现有方式管理。

## 比较、停止与发布

- 固定项目初态、模型、工具权限与预算后开始比较；单轮比较为默认，开始前设定预算／轮数／无改进停止条件，任一条件到达即停止新增运行并保存结果。故障与异常计入运行结果，不只保留成功样本。
- **建议更新的条件**：候选达到预设目标且关键案例（含保留案例）无退化；关键回归或保留案例失败时不建议更新。结果不充分时保持默认版本。
- **发布**：维护者审核具体差异和评测依据后才更新团队默认版本；第三方依赖记录固定版本，不修改全局安装副本。发现回归时退回上一个已验证版本，保留失败案例与证据。
- 随机性大的结论需重复运行或明确样本不足；跨模型／跨宿主结果分组报告，不混合成单一分数。

## 结果记录

每次运行记录：案例与版本标识（提交或快照哈希）、环境与启动规格、断言结果、裁判结论、预算与停止状态、建议（建议更新／保持默认）及理由。运行记录与产物可追溯；不因一次失败自动改写团队默认规则。

交付时说明：被测变体、rubric、每个候选的注记、裁判判定、你的综合、是否推广该变体的建议。

## 边界与交付

遵守 [宿主合同](../nimo-mode/references/host-contract.md) 和 [委派纪律](../nimo-mode/references/delegation.md)。只读、方案或停止要求优先，步骤不扩大授权。推送、评论、发布等外部动作受用户当前授权约束。交付具体产物、当前版本证据、未完成项及原因。跳过保留理由，不能用 Skill 名称列表代替成果。
