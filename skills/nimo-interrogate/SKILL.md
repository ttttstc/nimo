# 独立质疑与审查

为用户配置的每个评审模型各派一名评审者，对抗性审查代码变更。每个模型拿到同一份提示词与评审标准。对抗性信号来自模型多样性，不是分配的人设：不同模型有不同的盲点、先验与推理模式。跨模型一致是高置信度信号；单模型发现值得读，但置信度较低。

交付物是一份综合裁决。不要自动应用修改。

## 委派机制

评审者用宿主提供的独立子 Agent／独立上下文派发，只读授权。宿主无独立上下文时诚实降级：主 Agent 亲自执行评审并明确记录降级；降级下的评审不称独立审查。宿主只有一种模型时，可用同模型的独立上下文，但必须报告缺少跨模型多样性，此时"跨模型一致"信号不可用。派发遵守 [委派纪律](../nimo-mode/references/delegation.md)。

## 步骤 1：确定范围

从上下文识别评审对象：

- 用户指向具体文件或 diff 时，用那个
- 在功能分支上时，运行 `git diff main...HEAD`（或合适的基线分支）拿完整变更集
- 用户消息引用最近的工作时，收集相关文件

把 diff（或文件内容）连同评审者理解代码所需的周边上下文文件一起打包。

## 步骤 2：陈述意图

派出评审者之前，显式陈述意图：这段代码想达成什么？从以下来源推导：

- 用户的消息
- 提交信息
- PR 描述（如果有）
- 代码本身

写出一段清楚的话。评审者挑战的是工作是否把意图执行好了，不是意图本身是否正确。对意图没把握时，先问用户再继续。

## 步骤 3：派出评审者

为用户配置的评审模型列表中的每个模型各派一名评审者，标签按评审者数量编号；用户未配置时，用宿主当前模型派一名评审者。全部评审者一次性并行派发（宿主不支持并行时按委派纪律串行派发，保持各自独立上下文）。

对每名评审者：

- 派发方式：宿主提供的独立子 Agent／独立上下文，只读授权
- 模型：用户配置的评审模型之一；未配置时用宿主当前模型

配置的模型在宿主上不可用时，从宿主实际可用的模型里选最接近的等价物（优先同家族中推理档位更高者）派发，报告该替换并建议用户更新配置；不因模型问题阻塞评审。配置值为"继承宿主模型"之类语义时，不单独指定模型，直接用宿主当前模型；不把这类配置当坏模型进入上述回退。

读 [评审者提示词模板](references/reviewer-prompt.md) 并填入：

1. 陈述的意图
2. diff 或文件内容
3. [评审标准](references/rubric.md) 的内容
4. [代码质量视角](references/code-quality-review.md) 的内容

同一份填充后的模板发给所有评审者，让每个模型都应用代码质量视角。每名评审者按模板规定产出结构化发现。

## 步骤 4：综合

结果陆续返回时，构建统一图景：

1. **解析全部发现**。
2. **识别共识**。被 2 个以上模型独立提出的发现是最高信号。
3. **识别单模型发现**。仍值得读，但相应降低权重。
4. **去重**。不同模型可能以不同方式描述同一问题。合并它们并记录哪些模型提出。
5. **记录分歧**。一个模型标记的问题被另一个模型明确说没问题，是对裁决有用的上下文。

## 步骤 5：负责人裁决

你是负责人评审者，一个务实的资深工程师，不是中立的聚合器。

读 [负责人裁决框架](references/lead-judgment.md) 获取完整框架。评审者只看到代码库的一个切片。你有完整上下文：目标、约束、时间线、哪些取舍已经考虑过。积极使用这些上下文。

把每个发现归入：

- **处理**。给定真实目标，影响正确性、安全或可维护性的真实问题。会阻塞一个真实 PR。
- **考虑**。合理，但你不确定现在值不值得为它付出处理成本。值得用户注意。
- **记录**。技术上有效但不可操作。依赖上下文、过早优化，或就当前阶段影响低。
- **驳回**。错的、吹毛求疵或缺上下文。附一行解释为什么。

每个发现附：哪些模型提出、类别、一行归类理由。

## 输出格式

按以下结构呈现裁决：

### 意图
> [步骤 2 陈述的意图段落]

### 评审者
- 评审者 [标签]：[模型]，[N 条发现]（每名评审者一行）

### 处理
[应当处理的发现。每条：描述、哪些模型提出、为什么重要。]

### 考虑
[值得想一想的发现。每条：描述、哪些模型提出、涉及的取舍。]

### 记录
[有效但低优先级。简短列表。]

### 驳回
[被拒的发现及简短理由。让用户看到被过滤掉了什么、为什么，用户不同意时可以推翻你的判断。]

### 一致性图谱
[模型在哪里一致、在哪里分歧，一致／分歧的模式说明了什么。]

## 边界与交付

遵守 [宿主合同](../nimo-mode/references/host-contract.md) 和 [委派纪律](../nimo-mode/references/delegation.md)。只读评审，不自动应用修改；只读、方案或停止要求优先，步骤不扩大授权。交付具体产物、当前版本证据、未完成项及原因。跳过保留理由，不能用 Skill 名称列表代替成果。
