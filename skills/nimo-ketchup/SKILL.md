# 追平

用户上一条消息之后发生的变化，讲到他明白每一处变化是什么，而不只是走到哪一步。然后把所有等他拍板的事摆出来。

默认他记得自己最后那条消息，之后的一概不记得。通知与子 agent 的返回值不是他的消息，不能当成「他没回音」。

## 先收集

本轮流保持只读：不改代码、不起应用、不跑任务、不对外发布。

- 变化来源三层：本会话里自己做的事、子 agent 的报告、会话里其他人的消息。
- 逐项核实状态：这次会话碰过的 PR、CI、后台任务，去查当前真实状态，不用记忆。
- 要展示的数字先对回它的事实来源；发现自己上次说错了，就直说改口。

## 什么算等他定的事

只有他能做的事才算：产品取舍、批准、不可逆操作、我没有的权限。

- 他上一条消息之前提出、至今还在等他的，也要列。
- 我自己还能做的，不算等他定。
- 不要为了凑数编一件事出来。没提出的、活也不需要做的，不算；除非不可逆且正等他，那也只给一行、不配图。

一件等他定的事可以覆盖很多东西，比如一组 PR 一起等合并。每项收集：链接、它对用户意味着什么、我这么选的理由、风险、我的选择。缺的事实写「未知」，没有链接就不放链接。

## 怎么写

字数花在等他定的事上，不花在讲故事上。

- 开头一句就说清在等什么；没有就直说没有，然后停。
- 「发生了什么」控制在 100 字以内（不含图），事情少就更短。对用户没有任何影响的过程不写。
- 每件等他定的事约 30 字。条目多就写长，不要为了压字数砍条目，也不要用一个链接代替一条内容：只有这条回复本身就要够他做决定。
- 开场之后先放图，再放总结，最后列待定事项。
- 总结一件事一行，按他提过的顺序：结果是什么、做完了还是在跑、失败还是没查。照口语写（「搜索慢是因为少了索引」，不是「搜索评审：完成」）。顺手发现并修掉的缺陷单独写一行。每行单独读也得成立。
- 已经做但还在等他定的，不能写成已完成；待定事项里说过的，总结里不重复。

## 待定事项怎么写

先问那一句：合并、批准，还是挑一个。再给我的选择。

- 我会先做的、必须先做的、不可撤销的，都写进「我的选择」。
- 写清每项对应的 PR、issue 或后台任务的编号或链接，二选一的选择里也要写。
- 一项一件事就一条：这件事、我的选择、对用户意味着什么、依据、风险，对象只提一次。
- 多项共用一件事：这一件事与我的选择写一次，然后每项一条，最危险的在最前：链接与名字、对用户意味着什么、依据、风险。风险跟共有选择不同时才单独写；每项都要写风险，哪怕很低（「低风险：只改颜色」）。
- 等待的代价大于「晚一点」时才写代价，比如有截止时间或会丢数据。
- 在选项之间做选择时：每个选项都给能得到什么、要付出什么、当前状态；这些代价就是风险，不再另写风险行。选项有截图时，得失写在该截图下面。

## 图

图是图片：截图、录屏、Mermaid 图、图表、生成的图像。Markdown 表格不是图，带前后对比列的表也不是。

- 一句话讲不清的结构才画：设计怎么运作、PR 栈与依赖、修复前后、选项并排。
- 不画状态清单、不画待办清单、不画彼此无关的方框。
- 每个图一眼能读完：最多六个框，每框最多八个词；标签用人话，不写「Tests: pass」这类标签。
- 需要一句话才说得清的事实放正文，或者干脆不放。
- 变化在屏幕上看得见就内嵌截图或录屏，不要只给链接；没有就说「暂无截图」并说清变了什么。
- 只画手上真有的东西：没量过的数不画，没截到的屏幕不画，链接只给真实存在的产物。

## 视频变体

只在用户明确要视频、动画或录屏时走这一段。窗口起点、待定事项、只读边界都不变，改动只有一处：把「发生了什么」从图文换成无声带字幕的幻灯片视频，写在仓库外，这是只读规则的唯一例外。

- 先用一句话写下用户看完该带走的那一句，再每页写一行。这一句与每页那行都不出现在回复里。
- 最多十页，能少则少。不改变用户认知的页直接删。
- 每页只讲一件事，在同一个画面上逐页加东西，不切到无关画面。颜色与形状的含义每页一致。
- 展示工作本身：系统怎么运转、PR 栈各自状态、修复前后、选项并排。用箭头、高亮与动效指向变化。一页不许是项目符号、状态清单、表格，或彼此不相连的方框。
- 字越少越好，标签贴在被命名的对象上、用人的说法。不解释画面里已经画出来的内容，同一事实不在页与页之间或字幕里出现两次。
- 只画手上真有的：没截到的屏幕不画，没量过的数不画。已经完成但还在等用户的事不许画成已完成。
- 每页一条字幕，约十个词，说这页意味着什么，不念标签。字幕放在页下等高、除此之外留空的条里，不压住画面，聊天尺寸下要能读。
- 每页停留时间按这页新增的字算：每秒三个词，最少一秒。截图里的字不算。
- 渲染完抽帧核对：每页取一帧在聊天尺寸下看字幕是否可读、是否压住画面；用帧与页面对齐的方式量停留时间，不用静止帧检测。读不完就改这页、重渲、再核。
- 渲染失败就用一行说明，然后只给待定事项。宁可少给视频，也不硬造画面。

回复结构：ketchup 的开场一句、内嵌视频、一行说明还有哪些活自己能做、待定事项清单。视频里给选项起了名，正文就用那个名字指代。

## 边界

- 不改代码、不开 PR、不替用户做他的决定。
- 用户没问的事不展开；要展开就给链接。
- 与 `nimo-show-me-your-work` 的分工：那个讲「我做了什么、证据在哪」，本技能讲「从你上次说话到现在变了什么、你在等什么」。
