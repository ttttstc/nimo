# 爆炸半径

[how](../nimo-how/SKILL.md) 告诉你代码做了什么。[why](../nimo-why/SKILL.md) 告诉你它为什么长这样。爆炸半径回答第三件事：它会在**别处**弄坏什么。

只列出调用方不算完成。调用方列表是起点，不是结论。

## 别信自己写的报告

一份读起来很对的爆炸半径报告没有价值。它和真正的结论长得一模一样，区别只在于其中一两个事实到底做过没有。

找出整份结论依赖的那一两个事实，再用跑得起来的代码把它们证真。文字是起点，不是交付物。

## 你有多确定

任何一条安全结论，先定位它在下面哪一级。级数是自报的，别人会按你的自报来验收。

1. **你说过。** 自身无价值。只说明有人讲过这句话。
2. **指到行。** 给出真实的 `file:line`，或指向库源码。真实代码可以，回忆不行。
3. **证明坏情况到不了。** 比如：唯一调用方传的是常量。
4. **跑过。** 写脚本或测试调用真实代码；错了会响。
5. **在运行的应用里复现过。** 最强，也最贵。

任何一条到不了第 4 级的安全事实，当面说出来。可以写进报告，但必须写成未证，不能写成已定。

## 步骤

1. **读改动。** 实际变了什么语义，不是 diff 里有多少行。

2. **找那个事实。** 整份结论里，哪一句是「它安全是因为……」？通常是「只有这个调用方」「这个字段总是存在」「这个函数在渲染前就跑完了」。一句就够，别写十句。

3. **在 grep 停下的地方继续。** 调用方查干净了，接着往这些地方看：
   - 库源码，以及仓库里钉住的版本与本地补丁
   - 微任务时序、unmount、teardown 的顺序
   - 框架差异（两个框架的更新时机不同，同一段代码语义不同）
   - 接口真的返回 JSON 还是别的实体
   - 数据库列的真实约束，而不只是文档写的
   - 线格式：还有另一个语言在读同一批字节
   - feature flag 的两侧
   - 下游第三跳之后谁在消费

4. **诚实评估风险。** 每条风险给概率与代价，可以粗略，但要有真实 `file:line` 支撑。搜索为空也是答案——「没有任何调用方」是可用的结论，前提是你真搜过。绝不编造调用方、API 或行为。

5. **证明那个事实。** 写脚本或测试，跑真实代码。证不了就标 unproven，不要四舍五入成「应该没问题」。第 3 级结论（证明坏情况到不了）也算证明，但要在报告里说明是静态推的。

6. **大范围改动按 [arena](../nimo-arena/SKILL.md) 跑。** 多个模型问同一个问题，合并答案——它们漏掉的点通常互补。

## 交回什么

五节，按顺序：

- **它做什么。** 一句话。
- **它安全所依赖的那个事实。** 说明停在哪一级，附上证明（脚本路径、测试名、跑出来的输出）。没证就写 unproven。
- **风险。** 概率 × 代价，带 `file:line`。
- **已排除。** 检查过但确认影响不到的路径，各一句话，说明怎么排除的。
- **合入前。** 最便宜的测试或复现方式，含你自己写的那个脚本。

## 边界与交付

读取、搜索、跑脚本、写临时探针都在授权范围内。写进项目源码的改动仍按 [宿主合同](../nimo-mode/references/host-contract.md) 与 [委派纪律](../nimo-mode/references/delegation.md) 走：动手前说明要改什么，改动交 [nimo-verify](../nimo-verify/SKILL.md) 在真实操作面上验证。

结论写出来过一遍 [nimo-unslop](../nimo-unslop/SKILL.md)，引用真实代码，去掉任何私有信息。
