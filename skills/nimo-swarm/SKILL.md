# Swarm（扇出并行工作者）

扇出 N 个并行工作者。它们可以分别覆盖不同的分片、按相同任务书竞赛，或两者混合。父 Agent 等待、汇总，并返回一份报告。

## 委派机制

工作者通过宿主提供的独立子 Agent／独立上下文派发，遵守[委派纪律](../nimo-mode/references/delegation.md)。宿主无独立子 Agent 时诚实降级：主 Agent 按委派纪律顺序扮演各工作者，明确记录降级，不伪造并行与独立性。

## 开始

启动任何工作者之前，先建一个待办列表，每个阶段一条：

1. 定框架
2. 扇出
3. 汇总
4. 报告

## 阶段 A：定框架

1. 说清完成判据，以及 swarm 必须返回的产物或报告。
2. 选择形态。把工作切成分片让工作者分别覆盖、让 N 个工作者按相同任务书竞赛，或两者混合。竞赛或混合形态时，在派发之前声明选择规则：首个通过（`first pass`）、全排名（`rank all`）或择优（`best-of`）。
3. N 由用户指定，或从形态推导。N 是工作者总数，不是执行环境的并发上限。
4. 工作者模型：用户明确指定时使用指定模型；未指定时使用宿主当前模型。模型竞赛（每组用不同模型）时，预先声明每组的模型。
5. 有写操作的工作者，每个都要有自己独立的可写输出位置。用 worktree、分支，或系统临时目录下的 `swarm-<slug>/worker-<n>/`。

## 阶段 B：扇出

一次性派发全部 N 个工作者，使用阶段 A 确定的模型，每个工作者是宿主提供的独立子 Agent／独立上下文。宿主不支持并行派发或后台执行时，按委派纪律串行派发并保持各自独立上下文，明确记录降级。仅当工作者需要访问用户本机上的资源时，才为其选择具备本机访问能力的执行环境。

工作者必须从非默认的已推送分支起步时，在其任务合同中写明起始分支。

每份任务书独立成立。包含：目标、范围、确切的分片或竞赛分组、如何验证、报告什么。报告用 `PASS`、`ISSUES` 或 `BLOCKED`，附证据。

有工作者中途退出时，用 N-1 继续，并注明。

## 阶段 C：汇总

读取全部终止结果。覆盖形态下，每个必要分片都必须有结果，缺任何一个必要分片的结果即不完整。竞赛形态下，应用预先声明的选择规则：首个通过、全排名或择优。不粘贴工作者的原始输出堆。

保留一张紧凑的结果表、每条问题一行的证据、以及明确列出的缺口或退出者。

## 阶段 D：报告

在对话中返回一份整合报告：结果表、单行问题、缺口或退出者，以及使用竞赛时说明所用的规则。

## 边界与交付

遵守 [宿主合同](../nimo-mode/references/host-contract.md) 和 [委派纪律](../nimo-mode/references/delegation.md)。只读、方案或停止要求优先，步骤不扩大授权。交付具体产物、当前版本证据、未完成项及原因。跳过保留理由，不能用 Skill 名称列表代替成果。
