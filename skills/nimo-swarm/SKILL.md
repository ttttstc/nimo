# 并行执行与汇总

把任务分给 N 个独立执行者。它们可以分别覆盖不同分片，也可以在同一任务上竞速比较。父 Agent 负责等待全部结果、检查完整性并汇总成一份报告。

## 委派机制

执行者通过宿主提供的独立子 Agent／独立上下文运行，并遵守[委派纪律](../nimo-mode/references/delegation.md)。宿主没有独立子 Agent 时，由主 Agent 按相同合同顺序执行各分片，明确记录降级，不伪造并行性或独立性。

## 开始

启动任何执行者之前，建立任务清单：

1. 定义范围与完成条件
2. 并行执行
3. 汇总结果
4. 输出报告

## 阶段 A：定义范围与完成条件

1. 明确完成判据，以及最终必须返回的产物或报告。
2. 选择执行方式：
   - **覆盖**：不同执行者负责不同分片。
   - **竞速**：多个执行者处理同一任务。
   - **混合**：既有分片，也在部分分片内竞速。
3. 使用竞速或混合方式时，派发前明确选择规则：首个通过、全部排名或择优。
4. N 由用户指定，或根据任务分片数量推导。N 是执行者总数，不等于宿主并发上限。
5. 用户指定模型时按要求使用；未指定时使用宿主当前可用模型。需要比较模型差异时，派发前明确每组模型。
6. 有写操作的执行者必须拥有独立可写位置，例如独立 worktree、分支或临时目录，避免共享可变状态。

## 阶段 B：并行执行

宿主支持并行时，一次性派发全部 N 个执行者；不支持时按委派纪律顺序执行，并保持各自上下文隔离。

每份任务合同必须独立成立，至少包含：目标、范围、负责的分片或竞速组、验证方式和返回格式。每个执行者用 `PASS`、`ISSUES` 或 `BLOCKED` 报告，并附证据。

执行者中途退出时，继续处理其他结果，并明确记录缺失项；不能把缺少必要分片的结果报告成完整覆盖。

## 阶段 C：汇总

读取全部结果。

- 覆盖方式下，逐项确认每个必要分片都有结论。
- 竞速方式下，应用阶段 A 已声明的选择规则。
- 混合方式下，先检查覆盖完整性，再在对应分片内应用竞速规则。

不要直接堆叠执行者原始输出。保留紧凑结果表、每条问题的证据，以及明确的缺口和退出者。

## 阶段 D：报告

输出一份整合报告：执行结果表、关键问题及证据、缺口或退出者，以及使用竞速时实际采用的选择规则。

`nimo-swarm` 负责并行覆盖和执行汇总。需要针对同一非简单产物生成多个完整候选、统一评分、选择基线并整合优点时，使用 [nimo-arena](../nimo-arena/SKILL.md)。

## 边界与交付

遵守 [宿主合同](../nimo-mode/references/host-contract.md) 和 [委派纪律](../nimo-mode/references/delegation.md)。只读、方案或停止要求优先，步骤不扩大授权。交付具体产物、当前版本证据、未完成项及原因。
