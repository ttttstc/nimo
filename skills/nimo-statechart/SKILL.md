# 状态图

用读者看得见、能判断对错的语言展示系统如何改变状态。状态图来自有限的 TLA+ 模型，不等于对真实系统的运行验证。只建立本次问题需要的模型，说明假设和遗漏。

## 准备与运行

在仓库外的临时目录编写 `SPEC.tla` 和 TLC 配置文件；用户指定了其他交付路径时遵守其授权。运行：

```sh
node <skill-dir>/scripts/statechart.ts <scratch>/SPEC.tla --config <scratch>/SPEC.cfg --view <scratch>/view.mjs --out <scratch>/result
```

`--config`、`--view`、`--out` 可省略；默认配置为规范旁的 `SPEC.cfg`，默认输出为 `SPEC-chart`，默认标签展示状态值。输出目录必须不存在或为空；已有文件不会被覆盖。命令以退出码 0 表示规则通过、1 表示规则被违反、2 表示检查出错；处理 `SIGINT` 或 `SIGTERM` 时分别返回 130 或 143。

需要 Node.js 22.18 及以上的 22.x，或 23.6 及以上版本。Unix 上也可运行 `sh <skill-dir>/scripts/statechart ...`，该启动器还支持 Bun 1.1.5+ 和 Deno 2+。Windows 原生环境使用上面的 Node 命令。

TLC 需要 Java 11+。若环境变量 `TLA2TOOLS` 指向已有 `tla2tools.jar`，脚本使用它和 `JAVA` 指定的 Java（未指定时使用 `java`）；否则脚本通过 mise 查找并可能安装固定版本的 Java 和 TLC，需要网络和 mise。开始前说明依赖及可能的安装；缺少运行条件时报告受阻，不把草图称作已检查的图。

## 编写模型

- 把读者认可的每条规则写成 `INVARIANT`；规则可涉及画面、结果、存储值或消息。缺少表达规则的变量就补充变量，不为通过检查而弱化规则。
- 将 `Next` 写成各动作的析取，如 `YouPressPlay \\/ YouPressStop`，使 TLC 能区分步骤名。
- 没有后继步骤的状态会被判为死锁，正确的终态也一样。对于允许停止的终态，给 `Next` 增加仅在终态成立且 `UNCHANGED vars` 的动作，并在视图中命名。已有同名规则时，死锁规则显示为 `CHECK_DEADLOCK`，否则显示为 `NoDeadlock`。
- 收紧常量规模或加入 `CONSTRAINT`，避免无界探索。模型、规则和边界需要读者确认；不能把缺失的业务要求猜成事实。

## 编写视图

在 `--view` 指定的 JavaScript 模块里导出 `state(vars)`：返回字符串得到平面图，返回数组得到嵌套状态，返回对象得到并行区域。状态名写读者关心的事实，例如“正在支付”，不使用变量名。TLA+ 序列在 `vars` 中从 1 编号，集合表示为数组。

可选导出 `step(action, from, to)`、`group(vars)`、`colors` 和 `title`。步骤标签描述读者看到的动作或结果；条件用读者的语言放在方括号内。并行区域对其他区域自动生成条件，不要手写会覆盖它们的条件。相同的可见结果使用相同标签。分组颜色可用 `blue`、`orange`、`purple`、`yellow`、`teal`、`tan`、`pink`；同一标签背后的模型状态属于不同分组时，该标签不着色。

这些函数只依赖参数：脚本对每个模型状态的 `state` 和 `group`、每个步骤的 `step` 最多各调用一次，图和报告共用结果。两个模型状态落入同一标签时，图不画标签内的步骤；重要步骤需要拆开标签。

尽量控制在约 20 条箭头内，先合并对读者行为相同的状态，再考虑让 `step` 返回 `null` 隐藏不必要的步骤。保留每条问题路径、每个问题标记和不同规则的区分；不能把 `breaks` 合并成掩盖具体问题的 `mayBreak`。隐藏步骤时，每个图状态仍须从起点可达，有后继的状态须保留至少一条出边，同一箭头对应的步骤要么全部保留要么全部隐藏。交付时列出隐藏了什么。

## 阅读结果

- `chart.mmd` 中 `breaks` 表示该标签背后的状态都违反所列规则，`mayBreak` 表示只有部分状态违反。图例列出规则；并行区域的标记按状态组合计算，交付时指出具体状态和规则。
- 检查会继续探索违反规则后的状态。配置含 `VIEW` 或 `SYMMETRY` 时，图使用 TLC 选出的代表状态，箭头可能指向代表而非步骤实际抵达的状态。
- TLC 会检查越过 `CONSTRAINT` 或 `ACTION_CONSTRAINT` 边界的状态中的规则，但不继续探索该状态，也不检查其死锁；最短违规路径可能包含越界状态或被动作约束排除的步骤。不要把图视为边界外的完整状态空间。
- 脚本按原配置、单 worker 检查；发现违规后移除该规则再检查其余规则。首次违规后的每次运行最多探索 100,000 个不同状态；触及上限或出错时，报告列出未检查的规则，它们可能成立也可能不成立。缩小模型或移除已违反规则后再检查。该上限可能改变变量顺序和时序性质的反例。
- 图的预算为 500 个 TLC 状态。超过时只画违规路径；没有违规则不生成 `chart.mmd`。检查结果、状态数和问题路径仍在报告中。`tlc.out` 保存原配置的 TLC 输出；相关额外检查可产生 `tlc-RULE.out`。

## 交付

把 `chart.mmd` 作为 Mermaid 代码块展示。用户要求图片，或图过大难以阅读时，按 [渲染说明](references/render.md) 使用 Pele；渲染受阻时交付 Mermaid 和错误，不假称生成图片。

对每条问题给出规则、读者能理解的含义、报告中的编号路径；说明模型未覆盖的内容，并给出使用新输出目录重新运行的命令。模型对应现有代码时，逐步对照真实代码复现问题；无法复现时先检查模型，明确保留未验证项。
