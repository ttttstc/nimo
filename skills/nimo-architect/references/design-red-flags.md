# 设计红旗

综合之前逐条筛查每个候选。一面红旗就是修订或拒绝该形状的理由。

## 浅模块

浅模块暴露一个很大的接口，却几乎没有隐藏复杂度。深度按公共面背后的能力与策略、相对该面的大小来判定。优先选择由实质行为支撑的简单接口。

不要把深模块和深调用链混为一谈。深调用链把理解打散到各层；深模块把能力集中到一个接口之后。

关注这些迹象：

- 调用者要协调多个方法才能完成一个操作。
- 公共选项暴露了内部阶段或实现选择。
- 学会了接口，调用者依然免不了要学会实现。

## 信息泄漏

信息泄漏让多个模块依赖同一个内部决策。一个表示、策略或协议细节出现在多于一处，改动它就需要协同编辑。

传输层或线上格式的公共再导出就是泄漏。在接口后面把外部数据解析成领域类型。存储 schema、框架对象、协议细节保持私有。

## 时序分解

时序分解按执行顺序、而不是按拥有的知识来组织模块。加载、校验、转换、保存分开成多个阶段，常常让同一份数据表示和它的不变量在多个边界上重复。

围绕领域知识和所有权组织代码。运行在不同时间的方法，只要保护的是同一组决策，仍然可以属于同一个模块。

## 透传方法

透传方法把相同参数原样转发给另一个同形方法。它增加了一层，却没有隐藏任何复杂度。

删掉它，或者把职责移到能独立完成整个操作的模块。只有当转发边界增加了策略、适配或一个独立抽象时，才保留它。

## 拆分所有权

多个模块写同一份状态，或者各存一份副本。改其中一个写入者的 agent 看不到其他写入者，它们的规则就会分叉。

给每份状态一个 owner。其他模块读它，或者请求 owner 去改它。

## 同一任务两种做法

设计支持同一任务的多种做法。agent 会复制它先找到的那种，于是每种做法都在持续获得调用者。

只保留一种做法。在同一变更内迁走其他做法的调用者并删除它们。

## 可导入内部实现

调用者能 import 某个模块的内部实现。agent 走最短能编译的路径，直接 import 内部，内部实现就成了接口的一部分。

让内部实现在模块外不可达，从外部 import 它会构建失败。

## 手工同步清单

两个以上位置罗列同一批条目，加一项要改每一处。只看到一个清单的 agent 只会改那一处。

保留一份清单，其余从它派生。无法派生时，让清单不一致导致构建失败。

## 删除检验

判断一个模块是否值得保留：删掉它，复杂度会消失，还是散落到调用者？散落说明它在隐藏复杂度（深模块）；消失说明它只增加了一层间接（浅模块，删掉）。

## 接缝与适配器

接缝（seam）是可替换行为的边界，也是测试的落点。优先选最高的接缝，越少越好，理想是一个：跨代码库的接缝越多，改动一处越容易漏改别处。

适配器计数是抽象是否成熟的信号。只服务一个实现的适配器是假想的抽象，两个以上才是真实的接缝。为一个实现就引入的间接层，等第二个出现再加。
