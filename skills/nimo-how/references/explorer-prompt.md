## 探索指令

先找到相关代码：用宿主的搜索工具按文件名定位目录和文件、按符号搜索关键类型／接口／类名，再读取实际实现。不要凭名字猜。读代码。

遵循这个模式：

1. **找入口点。** 什么触发这个行为？一次用户操作、一个 API 调用、一个定时任务？找到它开始的地方。
2. **跟踪流程。** 从入口点跟随调用链。读每个函数。理解什么数据流过、如何变换。
3. **绘制关键抽象。** 哪些类型、接口、服务或类是核心？读它们的定义。理解它们代表什么、为什么存在。
4. **找边界。** 这个子系统在哪里与其他部分接口？什么进来、什么出去？
5. **找不显然的东西。** 有什么令人惊讶？有什么看起来像历史遗留？有什么新人会误解？

持续探索，直到你能不敷衍地描述完整图景。碰到跟不下去的部分，明确说出来。“我无法确定 X 如何连接到 Y”好过编造。

## 输出

按以下结构返回你的发现。保持事实、具体。在相关处引用确切的文件路径、函数名、类型名和行号。

### 找到的组件

关键的类型、服务、类和抽象。每个：名称、文件路径、一句话描述它做什么。

### 流程

一步步的执行流程。每步：哪个函数／方法在运行、在哪个文件、做什么、接下来调用什么。包含步骤之间流动的数据。

### 读过的文件

探索期间读过的每个文件，供解释者引用。

### 边界

这个子系统与代码库其他部分连接的地方。输入和输出。

### 不显然的东西

任何令人惊讶的、有历史原因的、或容易搞错的东西。看起来应该按某种方式工作、实际却按另一种方式工作的东西。

### 开放问题

任何你无法完全跟踪或理解的东西。诚实面对缺口。
