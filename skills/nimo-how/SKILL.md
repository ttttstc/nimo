# 理解系统与审视架构

## 步骤

1. 先确定问题、入口和范围。窄问题直接读实际代码；跨模块问题划分不重复的调查角度。
2. 跟踪输入到输出的调用、数据与状态，读取真实定义和调用者，返回文件位置、事实和未知。
3. 复杂调查可委派不同切面，再汇总矛盾。不能只给文件名而不确认访问条件。
4. 输出概述、关键概念、运行机制、位置和易错点，不逐行复述代码。
5. 审视模式先理解，再让独立上下文提出问题；主 Agent 核实，分为处理、考虑、记录和驳回，不自动修改。

## 边界与交付

遵守 [宿主合同](../nimo-mode/references/host-contract.md) 和 [委派纪律](../nimo-mode/references/delegation.md)。只读、方案或停止要求优先，步骤不扩大授权。交付具体产物、当前版本证据、未完成项及原因。跳过保留理由，不能用 Skill 名称列表代替成果。
