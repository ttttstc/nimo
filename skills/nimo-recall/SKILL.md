# 重建上下文

开始或接着干活之前，先把用户最近的工作上下文重建出来，交回一份很短的胶囊：现在到哪一步、下一步做什么。

只读在范围内需要的，读完就停。

## 两个来源

- **本会话历史**：做过什么、定过什么，在这条对话里。
- **共享记录**：同一块代码在别处留下的东西——用户反复报的症状、已上线又被回滚的修复、还在报的错误。这部分来自版本库、问题单、聊天与讨论、长文档、错误跟踪。

一个功能缺陷尾巴长，故事大多在共享记录里，只靠自己的对话记录重建不出来。所以：主题点到某个功能、文件、子系统、区域或缺陷时，共享记录这一扫是默认动作，不是可选项。

## 一、先分类再选路

- 要接着某一次具体的对话 → 走 playbook `session-pickup`，不是本技能。
- 要把习惯固化成技能 → 走 `nimo-skill-author`。
- 只是要一份给别人看的工作总结 → 另说，不是本技能。

用户已经给了完整状态（路径、分支、改了什么）就直接用，跳过挖掘。

## 二、先锁范围

- 时间窗：「最近」要给实数，默认最近 7 天。
- 主题：用户点名了就只做这个。
- 工作区：默认当前这个；没被要求就不读别的项目。
- 把范围回述一遍再开始。绝不把「全部」悄悄变成「最近若干条」。

## 三、挖会话历史

- 会话记录由宿主提供。宿主的记录在哪、能不能读，先确认；读不到就说读不到，改用用户给的状态或当前活状态，并在简报里写清来源缺失。不要假装重建过。
- 宿主能开子 agent 时，按切片并行：每个子 agent 一小块，按真实修改时间排序（不用文件名排序），先按主题检索再只读命中的那几段，跳过当前这条会话与明显噪音（子 agent、评测、测试会话）。
- 每个子 agent 回同一份结构，一条会话一块：主题、用户目标、决定、未完结的线、卡住与纠正、产物（PR、工单、分支），都要带来源标识。
- 只有一两条会话时不并行，直接读。
- 原始记录留在子 agent 里，主线程只拿结论。
- 宿主不支持子 agent 时由主线程顺序做，并在简报里说明「未做独立并行检索」，不得说成独立复核。

## 四、扫共享记录

- 交给 `nimo-why` 的来源调查去扫，但把问题从「为什么这么做」改成「现在什么状态、试过什么没站住、用户还在报什么」。
- 与第三步并行；一个来源一个调查者，查不到也是结论，要写。
- 没有宿主的某个接入（MCP 之类）就跳过并说明。
- 只是「这周我干了什么」这种纯活动回顾、没有命名对象时，可以跳过本步。

## 五、对活状态核实

挖掘与扫查出来的 PR、分支、工单，用 `git` 与 `gh` 查当前真实状态。结论取决于某个后台任务实际做了什么时，读它的完整记录，不读裁剪过的副本。

## 六、按契约写

先说胶囊，再说线，再说问题，最后下一步。更细的内容放后面或者砍掉。

- **胶囊**：最多 5 条，这块工作是什么、整体到哪。
- **线**：一行一条，前缀只用一个状态标签：`[已合并 #N]`、`[PR 待合并 #N]`、`[进行中 <branch>]`、`[已验证未提交]`、`[已回滚 #N]`、`[已计划未开始]`。没有标签的线不算完，必须打标签。
- **问题**：最多 5 条，只收反复出现的；包含用户还在报的症状与上线又被回滚的修复，让下一次从哪里跌倒就从哪里起步。
- **下一步**：只写一个最有用的具体动作。

相邻的功能或工单不进简报，除非它挡住这一件。胶囊与线放不下一屏时，先砍细节，不砍线。

## 边界与交付

- 全部过 `nimo-unslop`；会话结论按来源标识引用，共享记录按 PR 号、工单号、讨论链接引用。
- 对外输出前先脱敏。
- 不改代码、不开 PR、不写知识库；要写知识走 `nimo-knowledge-maintain`。
- 交付就是这份简报，不写「我检索了哪些文件」的经过。
