# 第一次跑通一个任务

下面是一条完整轨迹。输入只有一句：

```text
/nimo 帮我修这个 bug：导出任务重试时会重复写一行。
```

输出是一次带证据的交付。每一步都标出谁在做决定，以及这一步留下什么产物。

## 0. 说清楚三件事

- 决定者：你。
- 产物：一句目标、一个能判对错的完成条件、一条真实约束（例如「先复现」「不要改接口」）。

`/nimo` 后面跟什么，比跟多少重要。目标、判据、约束各一句够用；把步骤排好反而有害，排序是 playbook 的事。

**跳过会怎样**：只写「帮我修这个 bug」，agent 会自己挑一个它认为的 bug。三天后交付的修复，解的可能不是你在说的问题。

## 1. 入口判意图，挑 playbook

- 决定者：主 agent。
- 产物：任务清单。选中的 playbook 编号步骤原样拷进清单，可细化，不可静默删。

请求里出现「重试」「重复写」这类词，加上一个能判真假的完成条件，落在 [缺陷修复](../../playbooks/bug-fix.md) 上。判不了意图就按指导处理：只给判断，不产生副作用。

**跳过会怎样**：没有 playbook，就没有固定步骤。复现、定位、验证这三步谁先谁后由模型即兴决定，最常见的结果是直接改代码，然后拿「看起来对了」当验收。

## 2. 进入流程先读原则正文

- 决定者：主 agent。
- 产物：本任务真正生效的约束，写进计划和验证决定。

缺陷修复固定读四条：根因、最小改动、证明有效、可验证单元。读过索引不算读过正文；只读过索引时，不能声称已经应用。

**跳过会怎样**：原则退化成口号。修复会从「找到根因再改」滑向「在崩溃点加个判空」，症状消失，缺陷还在。

## 3. 先复现，亲自复现

- 决定者：主 agent。这一步不交给子 agent，也不交给用户。
- 产物：失败证据——复现命令、输出、日志、录屏，任何一个能重复跑出来的东西。

复现不了就先做只读调查；这种情况下，结论不能写成「已修复并验证」。真实环境够不到时，合成触发条件、收紧时序、加插桩，把控制面推到极限，再谈受阻。

**跳过会怎样**：没有失败证据，就没有「修好了」的定义。改动上线后，唯一能说的是「改了这段代码」，而不是「这个缺陷不再出现」。

## 4. 定位根因：nimo-how 打底，nimo-why 追史

- 决定者：主 agent 定方向；[nimo-how](../../../nimo-how/SKILL.md) 与 [nimo-why](../../../nimo-why/SKILL.md) 作为子 agent 扇出做调查。
- 产物：候选假设清单、逐个排除的记录、一个被运行时证据确认的幸存机制。

够不到机制就先补这一步。跨文件改动、受影响子系统不清楚时，nimo-how 必读；怀疑是回归时再叠加 nimo-why。猜出来的根因，会让后面所有设计一起错。

**跳过会怎样**：假设没被排除，就进入设计。三个方案都建立在错误前提上，评审一致通过，真实原因在隔壁子系统里继续触发。

## 5. 需要时才进 nimo-architect

- 决定者：主 agent 判断是否需要；语义边界不清时先用 nimo-grilling 让你拍板。
- 产物：一份设计，含结构不同的候选、比较依据、综合后的结论。只有设计，没有实现。

判据是「跨函数或模块边界」和「有实质取舍」。单函数内的最小修复不需要设计流程；反过来，改动会锁定一个以后很难换掉的结构时，跳过它省下的时间会在半年后连本带利还回来。

**跳过会怎样**：三个调用点各自长出一个小修补，形状互不兼容。下一次改动要同时理解三种约定，成本从这里开始复利。

## 6. 实现委派，diff 由主 agent 审

- 决定者：子 agent 写代码；主 agent 审 diff、做最终裁决。
- 产物：一个最小 diff，每一行都能追溯到前面的运行时证据。

「也许有帮助」的保险式改动不上线；证据推翻某个假设时，撤销它促动的改动。宿主没有独立子 agent 时由主 agent 顺序扮演，并在交付里记录降级——降级下的自审不算独立审查。

**跳过会怎样**：实现和验收由同一个角色完成，没人核对「改的是不是这个缺陷」。范围会顺带扩大：重构、格式化、顺手修的注释，一起混进 diff。

## 7. 验证统一走 nimo-verify

- 决定者：主 agent 定验收场景和最终判定；执行与证据采集可以委派。
- 产物：验收场景到验证资产再到证据的映射，结论只有通过、失败、未验证。

原始复现是必测场景，另加本次修复必须保持的关键不变量和最小相关回归。缺资产转 [nimo-verification-create](../../../nimo-verification-create/SKILL.md) 补，资产漂移转 [nimo-verification-maintain](../../../nimo-verification-maintain/SKILL.md) 修，然后回到 [nimo-verify](../../../nimo-verify/SKILL.md) 在真实操作面跑。

**跳过会怎样**：单元测试全绿，缺陷仍在。编译通过、类型检查通过、子 agent 自报完成，这三样都只是代理信号，不是结果。

## 8. 提交前跑 nimo-deslop

- 决定者：主 agent。
- 产物：只清理本次差异制造的问题——叙述性注释、无依据守卫、死掉的兼容路径、无关改动。

清理完要复验受影响的行为。不是本次差异制造的旧问题，不归这一步管；顺手清别人的代码等于扩大范围。

**跳过会怎样**：diff 里混进一半与本任务无关的改动。评审者分不清哪些行承载修复，回滚时连带删掉真正的修复。

## 9. 评审前跑 nimo-no-comments

- 决定者：主 agent，或独立的注释评审角色。
- 产物：每条新增注释的去留判定，以及能转成约束的项。

能由类型、运行时检查、测试或 CI 表达的约束，优先转过去，不留在注释里。注释解释「为什么」，不复述「做了什么」。

**跳过会怎样**：评审时间被花在讨论注释措辞上，真正的行为差异反而没人细看。

## 10. 交付

- 决定者：主 agent。
- 产物：结论（通过 / 失败 / 未验证）、证据位置、未完成项与跳过原因，以及一次轻量的知识影响判断。

推送、评论、合并这些外部动作，仍然受你当前授权的约束；验证通过不会自动带来授权。

**跳过会怎样**：结论含糊成「基本完成」。下一次接手的人要重新建一遍证据，等于这次验证白做。

## 跑完之后读什么

- 想少走弯路：[配方与坑](./02-recipes-and-pitfalls.md)，八种工况和十条常见错误。
- 想看完整路由：[入口路由表](../../SKILL.md)。
- 想核对自己这一跑：[nimo-inspect](../../../nimo-inspect/SKILL.md) 读任务记录、验证记录与证据状态，不重跑验证。
