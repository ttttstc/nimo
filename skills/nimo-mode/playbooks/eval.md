## 步骤

你拥有实验设计。规划、盲化、运行、综合。

评测在推广前测试一个变更如何影响 Agent 行为：新 Skill 变体、结构性变更、提示词微调。失败模式是观察者效应：知道自己在被评测的 Agent 行为会不同，所以候选必须盲跑。案例定义与运行规则遵循 [nimo-skill-evaluate](../../nimo-skill-evaluate/SKILL.md)。

盲化不可协商条款：

- 候选能看到的任何目录、文件或提示词里，不出现 eval、test、judge、experiment、rubric、score、compare、benchmark、candidate、arena 这些词。
- 候选提示看起来像自然的用户请求。陈述目标，不陈述元目标。"给我做一个小 todo 命令行工具"，不是"给我演示你怎么遵循原则链"。
- 不给诱发链式引用的提示。不问候选列出了它用过的 Skill、原则或文件；那种元提示会虚增引用行为。一般性地要设计笔记，链式遵循从代码形状评分，不从自报评分。
- 目录和 slug 名消毒。用用户会起的项目形名字，不是 candidate-1、agent-a 这类标签。
- 不告诉候选其他候选存在。
- 裁判可以知道自己在裁判，但只按消毒后的标签看输出，永远不按模型名。
- 比较两个变体：一个裁判在一次 pass 里用同一尺度给两组打分，盲于每组来自哪个集合。两次用不同提示词的裁判运行不可比较——校准会漂移。

1. **定框。** 陈述被测变体和什么行为算成功。给裁判写 rubric（3-6 条具体标准）。不给候选看。
2. **搭建消毒后的环境。** 每个候选一个工作目录，变体就位。植入自然任务会有的上下文：项目骨架、候选会自然读到的 Skill。
3. **写一条自然提示。** 用户会输入的东西。不泄露被测量的东西。
4. 按 [nimo-arena](../../nimo-arena/SKILL.md) 的阶段 B 派 N 个并行候选（用户配置的模型；未配置时在可用模型上各开一个，仅单模型可用时按委派纪律降级并记录）。每个候选在自己的消毒目录里工作；同一提示发给每一个。
5. 按 [nimo-arena](../../nimo-arena/SKILL.md) 的阶段 C 派一个盲裁判（优先不同模型家族）。裁判看到消毒标签的输出和 rubric，永远看不到模型名。
6. **从轨迹验证链式遵循，不从自报。** 读宿主为当前工作区记录的每个候选的执行轨迹（工具调用与文件访问记录）。不跨工作区搜索宿主的私有会话存储——那会越过工作区边界，读到无关项目的私人对话。看每个候选实际打开过哪些文件。引用一条原则不等于读过它的叶 Skill；读了不等于应用了。链式遵循从它真正读过的文件加代码形状评分，从不用候选自己的声明。宿主不提供执行轨迹时，涉及"实际读取"的评分记不可判定，不用自报顶替。
7. **亲自从头到尾读每个候选的输出。** 与裁判的判定比较。分歧意味着模型有偏或 rubric 有歧义。综合。

交付时说明：被测变体、rubric、每个候选的注记、裁判判定、你的综合、是否推广该变体的建议。

## 必要条件与停止

Skill 版本比较固定模型和环境；多模型比较单独标记实验变量。裁判不知道模型身份，执行者不知道其他候选存在；盲评不隐藏任务必要的验收要求，必须正常提供给执行者。候选工作目录和输入不泄露评分依据或候选身份。无法读取宿主工具轨迹时，涉及"实际读取过原则"的评分标为不可判定，不能用自报替代。裁判与主 Agent 判定分歧时，先查模型偏差或 rubric 歧义再下结论。推送、评论、发布等外部动作受用户当前授权约束。

公共规则见 [宿主合同](../references/host-contract.md)、[工具用法](../references/tools.md) 和 [检查点](../references/checkpoints.md)。
