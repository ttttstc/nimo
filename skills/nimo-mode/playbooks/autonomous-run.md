# 持续完成一个目标

标识：PB17。持续完成一个目标时使用；先遵守 [Mode](../SKILL.md)。

## 执行前读取

进入本流程先完整读取下列原则正文，不能用 Mode 索引摘要替代；读取后将相关约束写入实际计划与验证决定。已经在本任务读过同一版本正文时不重复读。用户明确排除的普通原则记录排除理由，强制门禁不可排除。

- [nimo-principle-sequence-verifiable-units](../../nimo-principle-sequence-verifiable-units/SKILL.md)
- [nimo-principle-prove-it-works](../../nimo-principle-prove-it-works/SKILL.md)

## 步骤

退出条件归你所有：先定义"完成"，然后不停顿地推进到它。适用于"我去睡了，你继续""做到完成为止""持续跟到 X 成立"这类请求。

1. 第一轮迭代之前，把退出条件写成可检查的判定谓词（测试全绿、复现已修复、全部 N 个 PR 已合入、像素差异为零）。目标模糊就会停滞；判定谓词给了你停止的依据。
2. 选择唤醒机制：仅当宿主提供原生等待／唤醒能力（事件监听、定时器、自动化）时才使用。有可观察事件（CI、一次合并、一个 ref 前进）就设一个事件监视者，事件发生时唤醒你继续，并以长时间隔的定时心跳兜底；没有可观察事件就用固定间隔心跳，间隔按"这个结果值得多久之后重查一次"来确定。宿主没有后台／定时能力时，明确本流程仅当前会话运行：会话存续期间推进，会话结束即停止，结束前保存恢复点并报告限制，不伪装后台能力。
3. 每轮迭代做证据支持的最小变更，对照判定谓词验证（结论按 [nimo-verify](../../nimo-verify/SKILL.md)）；谓词有推进就提交，没有帮助的变更就丢弃。"也许有帮助"的顺手加固回退掉，不是留着搭车。工作按 [分成可验证单元](../../nimo-principle-sequence-verifiable-units/SKILL.md) 原则排序，每个单元先验证再进入下一个，不把检查攒到最后批量做。
4. 运行中的发现归你处理。Skill 损坏、相关 bug、不稳定的验证器、审查噪音、工具故障、无人认领的遗留跟进、可修复的漂移——这些会阻塞目标的可逆问题由当前执行者按 nimo-mode 路由自行修复，不推给用户，也不用宿主的提问机制阻塞等待回答。题外修复放进单独 PR，不与主线变更混在一起。只有三类事项浮出给用户：不可逆动作、任何试验都无法裁决的真正产品或偏好取舍、真正的死路。判定谓词始终是主驱动；每次旁路修复之后回到主谓词继续。
5. 每轮迭代用 [nimo-show-me-your-work](../../nimo-show-me-your-work/SKILL.md) 写检查点：一行记改了什么、判定谓词是否前进。没有轨迹的运行既无法审计，也无法恢复。
6. 判定谓词满足时停止。平台期不是停止条件：换方法继续推进，突破它。宁可浮出真正的死路，也不要原地打转；绝不放低判定谓词来宣布胜利。

## 必要条件与停止

判定谓词满足即停止，且停止时谓词必须真实成立。用户停止、预算耗尽和真实阻塞不是成功，分别如实报告；不能靠降低完成条件来包装结果。平台期不是停止条件；真正的死路如实浮出，不放低谓词宣布胜利。

不把提示词当后台进程。记录退出条件和预算；宿主无持续运行能力时不承诺离线继续，只在当前会话推进，结束留下恢复点并报告限制，不建立私有服务或模型 API。唤醒后先核实目标是否已停止、取消或完成，再继续动作；每个目标只有一个有效跟进者，不叠加多套轮询。

会阻塞判定谓词的可逆问题由当前执行者自行修复（见步骤 4），修完回到主谓词；与目标无关且不阻塞谓词的发现记为后续跟进，不并入本轮变更。

公共规则见 [宿主合同](../references/host-contract.md)、[工具用法](../references/tools.md) 和 [检查点](../references/checkpoints.md)。

## 交付

报告退出条件、已运行的迭代轮数、落地的内容、丢弃的内容、最终判定谓词状态；附当前产物版本、实际验证和证据、未完成项及跳过原因。流程不自动授予提交、推送、评论、合并或发布权限；push、评论、合并、rebase 等外部动作受用户当前授权约束。
