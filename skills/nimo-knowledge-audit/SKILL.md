# 项目知识审计（nimo-knowledge-audit）

本 Skill 是严格只读的项目知识巡检。它判断“知识还对不对、Agent 还能不能低成本找到正确知识”，不负责修复。先完整读取 [知识维护契约](../nimo-mode/references/knowledge.md) 与 [配置规则](../nimo-mode/references/configuration.md)。

## 触发边界

只允许以下入口：

- 用户明确要求检查、审计、核对项目知识或知识索引；
- 用户或团队已经配置的定时任务、CI/外部例程明确调用本 Skill。

普通 feature、bug、refactor、设计或交付任务不得因为“可能有知识变化”自动运行本 Skill。`nimo-mode` 的交付前知识影响判断只是轻量信号，不等于审计。

## 结果

最终只给三种结果：

- **CLEAN**：在本次声明覆盖范围内，没有发现已确认的知识漂移或导航缺口。
- **DRIFTED**：发现至少一项已确认的事实漂移、覆盖缺失、索引/概览漂移或重要关系断裂。
- **BLOCKED**：无法完成可信审计，例如知识目标/项目证据不可访问、版本基线无法确定，或外部路径在当前宿主不可达。

“源码改过”只能说明知识可能陈旧，不足以判 DRIFTED。必须重新核对后证明事实或导航真的不再成立。

## 只读边界

- 不修改知识文件、`.nimo/nimo.yaml`、`.nimo/state/knowledge.json`、代码、配置或测试。
- 不为了让审计通过而改写预期，不生成“修复后的草稿”覆盖原文件。
- 可以生成临时审计笔记，但不得写入项目持久知识；交付时给出足够定位的证据。
- 未获得完整证据时标 BLOCKED 或明确局部覆盖，不能用“看起来没问题”输出 CLEAN。

## 检查维度

1. **事实漂移**：知识中的模块职责、调用关系、接口、数据、配置、运行方式等与当前项目事实冲突。
2. **覆盖漂移**：项目出现新的重要领域、模块、接口、Schema、配置契约或运行方式，但知识没有对应入口或事实。
3. **索引漂移**：Index 漏项、死链接、指向错误页面、摘要无法代表当前职责，导致查询被路由到错误知识。
4. **概览漂移**：Overview 的项目定位、核心领域、顶层模块、主链路或关键约束已经失真。
5. **关系漂移**：重要页面成为孤儿、关键交叉关系断开、重复知识互相矛盾或导航无法从 Overview/Index 到达。

## 流程

0. **定位范围。** 读取 `knowledge` 配置；没有登记目标时返回 BLOCKED，并说明先通过 `configure-nimo` 配置。用户指定某文件/领域时做 scoped audit；定时任务默认优先增量；用户明确“全量审计”时核对全部登记知识。
1. **读取维护状态。** `.nimo/state/knowledge.json` 只用于定位上次维护版本、目标所有权、事实来源和内容指纹。它缺失或损坏不能让审计伪装成 CLEAN；必要时退化为更广的只读核对。
2. **筛选疑似影响。** 增量场景比较最近可信维护版本与当前版本，识别变化的 Evidence Sources 和可能受影响 Knowledge Targets。新核心模块等没有旧映射的变化也要进入候选。
3. **核对事实。** 对候选知识逐项回到权威代码、配置、接口、测试或实际运行说明。区分“来源变化但事实仍成立”和“事实已经改变”。前者不报 DRIFTED。
4. **审视知识导航。** 从 Overview/Index 检查关键领域是否可达、条目摘要是否足以选择正确页面、链接是否有效、页面是否成为孤儿。新增/删除知识页时检查 Index；顶层领域或主链路变化时检查 Overview。
5. **抽查查询路由。** 选择与本次范围匹配的典型问题，仅依据 Overview/Index 选择下一跳；如果索引把问题引到错误页面、必须无差别扫描全仓才能找到目标，记录索引漂移。
6. **形成结论。** 对每项问题给出知识位置、当前知识主张、当前项目事实、证据、影响和建议的维护范围。
7. **停在确认点。** DRIFTED 时提示用户是否调用 [nimo-knowledge-maintain](../nimo-knowledge-maintain/SKILL.md) 更新；没有用户对写入的明确授权时到此结束。定时任务也只报告，不自行维护，除非该自动任务本身明确同时授权维护且由上层另行调用 maintain。

## 报告格式

DRIFTED 的每项至少包含：

```text
知识位置：<文件/标题>
类型：事实漂移 | 覆盖漂移 | 索引漂移 | 概览漂移 | 关系漂移
当前知识：<原有主张或缺失入口>
当前事实：<当前项目真实状态>
证据：<源码/配置/测试/接口等定位>
影响：<为什么会误导后续 Agent 或用户>
建议：<增量维护的最小范围>
```

CLEAN 也必须写明实际覆盖的知识目标和项目版本；不能声称“全仓无漂移”却只检查了一个模块。

## 与任务知识影响判断的关系

普通 nimo 任务在交付前可以产生 `REVIEW_RECOMMENDED`，表示“本次变更可能改变稳定项目事实”。这个信号不读取全知识库、不证明发生漂移，也不触发本 Skill。后续用户或定时任务可以优先根据这些信号选择审计范围。

## 完成标准

- 来源变化但事实不变时不误报 DRIFTED。
- 知识与当前项目事实冲突时能提供可定位证据。
- 新增重要能力没有知识入口时能识别覆盖/索引缺失。
- Overview、Index、Page 的可达性和摘要路由都在审计范围内。
- 审计全过程不产生知识修改；需要修复时停下并请求用户确认 maintain。
- 证据或访问条件不足时返回 BLOCKED，不把未知写成 CLEAN。
