# 验证真实用户结果

"能编译"不是证据。对着真实产物验证，不对代理指标——编译、类型检查、内部方法调用或子任务自报都不能替代原操作面。

验证结论只证明其绑定的当前产物版本。验证完成后，只要待交付代码发生语义变化，原结论不再证明新版本；交付前确认最后一次语义代码变化早于最后一次有效 Final Verify，顺序相反就必须重新验证。

## 步骤

1. 固定产物版本、验收场景与操作面，优先读项目 .nimo/verification/SKILL.md 和相关功能条目；当地图列出多个入口时，只驱动一个方便入口的验证是不完整的。当前变更已使相关 Verification Map 明显过期（用户入口、命令、路由、选择器、操作步骤或可观察副作用与地图不符）时，旧地图不能继续作为 PASS 依据：能更新就先更新受影响条目或辅助脚本再用新路径验证；不能更新就明确报告地图已漂移、当前验证不能成立。旧路径执行失败不降低预期换 PASS；旧路径恰好还能跑，不等于新行为已被验证。
2. 按变更类型选检查，用当前实际存在的终端、浏览器、设备或 API 工具：CLI 变更运行真实命令；UI 变更在运行中的应用里走一遍改动的流程；解析器或迁移重放保存的输入；性能变更比较前后 profile；存储变更读回写入的值。工具缺失不伪造：给出所缺前提，相关项记未验证。
3. 记录本次实例、端口、数据与所有权。任何时候情况看起来不对，先跑验证 Skill 的体检（进程存活、版本正确、端口归属、鉴权有效）再决定是否驱动。
4. 走真实用户路径，不走内部 setter 或测试专用端点；优先稳定句柄（ARIA 标签、data 属性、提示字符串、路由路径）而非坐标。捕获用户动作和结果状态，不只最终画面；副作用（写入的文件、插入的行、发出的消息）与可见结果一同验证。mock 只用在产品边界已隔离外部系统的地方。安全路径是 dry-run 或测试模式时，通过观察（文件、网络、git 引用）验证它实际跳过了什么，而不是相信它的名字：有些 dry-run 仍会碰网络或打开浏览器。
5. 先固定预期结果，再把实际输出逐项比对；只打印结果不算通过。保存版本、Shell、完整参数、操作、输出和时间。CLI 证明含命令、stdout、stderr 和退出码；变更证明含对已存储值的只读第二视图。更换 Shell 时确认参数含义相同，参数转发失败不能误判成业务结果。
6. 只清理本次实例；绝不按进程名杀，只杀自己启动的。证据在清理范围外，清理后在指名位置确认证据仍在。缺条件记未验证，不放宽预期。
7. 独立验证由未参与实现的上下文执行，主 Agent 再读取差异与证据验收。无法运行的检查如实报告"不可判定"；没有证据的自信结论是危险信号。

## 边界与交付

遵守 [宿主合同](../nimo-mode/references/host-contract.md) 和 [委派纪律](../nimo-mode/references/delegation.md)。只读、方案或停止要求优先，步骤不扩大授权。交付具体产物、当前版本证据、未完成项及原因。跳过保留理由，不能用 Skill 名称列表代替成果。
