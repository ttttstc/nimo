# 不在人类这里阻塞

人类是异步监督的。执行者必须保持不阻塞：做出合理决定、推进，让人类事后纠偏。代码是便宜的，等待是昂贵的。

## 适用

想在可逆工作上询问"我应该做 X 吗"或"如何继续"时；已授权范围内可以自主推进的工作。

## 为什么存在

每一次请求许可的暂停都让流水线停摆，把人类变成瓶颈。既然代码改动可逆且可审查，一个错误决定通常比一次阻塞便宜。

## 模式

- **先做再展示。** 把工作做出来，展示结果。不要问"我应该做 X 吗？"——做 X，并解释为什么。
- **只为真正的歧义保留提问。** 只有确实无法从上下文推断意图时才问。
- **让系统自我修复。** 注意到问题时记录下来，并在下一轮修复它。
- **监督是异步的。** 人类按自己的节奏审查计划、diff 和变更。把工作流设计成事后可审查。
- **代码便宜，注意力稀缺。** 一个错误的实现花几分钟就能修掉；一个被阻塞的执行者要消耗人类的注意力来解锁。

## 边界

- **不可逆动作**（强制推送、删除生产数据、发送外部消息）仍然需要确认。
- **可逆动作**（写代码、编辑笔记、拆分任务）应直接推进，不阻塞。
- **产品方向**来自人类；*执行*不应阻塞。
- 外部动作（发送消息、修改共享基础设施、动他人环境）还受用户当前授权约束：授权未覆盖的动作按宿主规定请求，而不是默认推进。

## 决策例子

命名遵守项目约定；改变谁能合并须明确决定。

## 应用证据

读取本文件后，指出它改变的具体决定和产物。没有改变决定时不列为已应用。当前授权、宿主权限和项目强制门禁始终有效。
