# 保留必要上下文

## 适用

大文件、复杂调查、委派和恢复；上下文正在被填满。

上下文窗口在会话内有限且不可再生。进入的每个 token 都应挣得自己的位置。

## 为什么存在

上下文溢出会降低推理质量、制造压缩失真并让进度停摆。与算力和时间不同，会话内花掉的上下文无法收回。

## 模式

- **隔离大载荷。** 把冗长的输出、截图和大文档路由给宿主提供的子 Agent；主上下文得到摘要，不是原始数据。宿主没有子 Agent 能力时诚实降级：大材料落盘，按需分段读取，主上下文同样只保留摘要。
- **不读用不到的东西。** 按相关性选择性读取。当前任务不需要的文件，跳过。
- **高频使用的内容保持内联。** 每次调用都会用到的模板和引用应放进 Skill 文件本身，而不是放进每次使用都要花一次读取成本的外部文件。
- **控制阶段规模并封顶范围。** 限制每个阶段的文件数，设定轮次预算，把机制本身的成本算进去。

## 决策例子

将跟踪文件转成可查询统计，只返回热点和证据位置。

## 应用证据

读取本文件后，指出它改变的具体决定和产物。没有改变决定时不列为已应用。当前授权、宿主权限和项目强制门禁始终有效。
