# 建立可重复的工具

## 适用

非简单修改、迁移、分析或验证；一切不琐碎的工作，不限于批量工作。

当工作不琐碎时，构建完成它的工具，而不是手工做。

## 为什么存在

两重回报。吞吐：改写脚本、生成器或脚本每次以同样的方式完成工作，复跑免费。信心：工具是审阅者可以阅读并复跑来检查工作的单一产物；手工改动只能靠重做来复核。确定性脚本把"相信我"变成"跑一下这个"。

## 模式

默认构建杠杆。只有当任务真的琐碎——一眼可见的几处显然改动——才跳过。

- 先手工做第一个单元来学会配方，然后构建工具。在同一个单元上复跑工具并与手工版本比对差异来证明它。让杠杆可以安全地复跑：审阅者会复跑。
- 编辑用改写脚本或脚本，重复性文件用生成器，分析用转储到 SQLite 再查询，验证用可复跑的检查。
- 确定性杠杆胜过扇出。如果工具能一遍处理所有单元，就自己跑它；不要把脚本能做的事扇出给委派执行者手工套用。
- 向子 Agent 扇出工作时，把杠杆写成一个所有委派者共同读取的 Skill：配方、验证契约和禁触边界放进同一个产物，让每个委派者继承同一个加固版本，而不是在每个提示词里重复解释、看着各自漂移。把它放在委派者的可写范围之外，使他们无法悄悄改动契约。
- 应用本原则会产生一个文件。如果你引用了它，而差异中没有改写脚本、脚本、生成器或委派 Skill，你就没有应用它。
- 当工作会存续到本次会话之后，把杠杆提交进版本库，让下一次运行复跑而不是重做（提交动作受用户当前授权约束）。

## 平衡

门槛是琐碎性，不是重复性。当杠杆正是让工作可检查的手段时，一次性工作同样配得上杠杆。依据[最少实现完整解决](../nimo-principle-laziness-protocol/SKILL.md)：构建能完成或证明任务的最小脚本，永远不要构建框架。

与[把重复错误变成约束](../nimo-principle-encode-lessons-in-structure/SKILL.md)不同：那条把重复出现的指令变成持久护栏；本条关心眼前这批工作的吞吐与可审阅性。验证本身的脚本化见[验证真实产物](../nimo-principle-prove-it-works/SKILL.md)。

## 决策例子

批量改名用可复跑脚本并检查全部引用。

## 应用证据

读取本文件后，指出它改变的具体决定和产物。没有改变决定时不列为已应用。当前授权、宿主权限和项目强制门禁始终有效。
