# 研发能力合同与选择顺序

nimo 不规定每个能力的内部实现，只约定输入、产物、证据与失败反馈。更换实现（Skill）后，按同一信息与证据要求验收。

## 六项初始能力

| 能力 | 目标与输入 | 必须形成的产物 | 必须提供的证据 | 失败反馈 |
|---|---|---|---|---|
| investigate 调查理解 | 目标 + 相关代码／规格位置 | 事实结论：结构、行为、数据流 | 引用的文件与行号、关键命令输出 | 说明查不到什么及已尝试路径 |
| specify 规格 | 用户结果描述 | 覆盖主路径与异常／取消行为的规格 | 与用户结果的对应关系 | 列出未能澄清的行为问题 |
| design 设计 | 规格 + 现有结构 | 方案与取舍说明（可并入规格，小任务不强制独立文档） | 方案对现有结构的影响点 | 说明未决的设计前提 |
| implement 实现 | 规格／方案 + 范围与保持项 | 代码差异 | 修改文件清单与自验结果 | 报告未完成项与受阻原因 |
| verify 验证 | 待验证产物 + 验收条件 | 通过／失败／未验证结论 | 实际执行的命令、观察结果与产物版本 | 说明缺失的运行条件 |
| review 审查 | 目标 + 实际差异 + 必要事实 | 遗漏与风险清单（可含“未发现问题”附范围） | 审查针对的差异版本 | 说明无法审查的范围 |

## 选择顺序

**用户本次指定 > 项目配置（`.nimo/project.yaml`）> 团队默认（`references/defaults/capabilities.yaml` 受控副本）> 当前环境中发现的适用能力。**

- 前一项不可用时说明原因；用户明确要求只能使用某实现时，不静默换用其他实现。
- 无效绑定（绑定的 Skill 不存在或缺 SKILL.md）阻止使用该绑定，如实报告绑定问题；不忽略错误后仍声称使用了指定 Skill。
- 关键选取结果在任务记录中留下实现与版本线索（Skill 名、来源）。

## 项目覆盖格式

项目配置位于 `.nimo/project.yaml`，只声明需要覆盖的项，未声明的使用团队默认：

```yaml
version: 0.1
capabilities:
  implement:
    provider: skill        # skill = 环境中已安装的 Skill；host-native = 宿主 Agent 原生能力
    skill: my-implement-skill
  verify:
    provider: host-native
```

## 回退与边界

- 缺少专业 Skill 时，可由宿主 Agent 原生能力完成，仍须满足相同的产物与证据要求。
- 缺少真实验证工具时记录“未验证”；缺少独立上下文时记录“独立审查未完成”，不把执行者自检标为独立审查。
- 不自动安装陌生 Skill，不动态拉取未审查脚本；能力发现仅使用当前宿主可见或项目已登记的能力。
- 第三方 Skill 的默认发布、提交和文件生成行为服从本次授权；不能安全裁剪时更换实现。
