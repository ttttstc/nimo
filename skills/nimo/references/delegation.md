# 子 Agent 协作纪律

委派把明确范围的执行交给子 Agent；目标、设计取舍、验收与交付判断始终留在主 Agent。子 Agent 的“已完成”是待核实的工作结果，不是交付证据。

本文件是宿主无关的协作约定：具体宿主如何启动子 Agent 见各宿主接入说明（`integrations/`）。nimo 不规定固定模型、推理强度、并发数量或嵌套深度档位。

## 委派触发

- **非简单实现默认委派**：跨多文件、需要调查或独立验证的 Bug／Feature 实现，交给子 Agent 执行，父 Agent 验收。
- 简单指导、事实问答和微小修改由主 Agent 直接处理，不判为遗漏。
- 用户明确要求不委派，或宿主不允许子 Agent 时：主 Agent 在现有范围内直接执行并说明原因；必要的独立审查缺口仍按检查点文件「完成检查与门禁」如实记录。

## 协作方式

按目的选择，不建设独立调度引擎：

| 方式 | 适用 | 约定 |
|---|---|---|
| 单任务委派 | 一个明确的调查或实现任务 | 父 Agent 验收其结果 |
| 分片协作 | 可独立调查或修改的范围 | 启动前列明必需分片；汇总时核对覆盖，缺少必需分片不算完成 |
| 候选比较 | 存在实质不同的设计方向 | 启动前明确比较目标与标准；候选写入隔离输出位置；全部完成写入后再独立评价；候选退出时记录比较范围缩小 |
| 独立审查 | 需要查找遗漏与风险 | 交给未参与该项实现的上下文；实现者不能担任自己的独立审查者 |
| 评测执行 | Skill 版本比较（由评测能力接入后展开） | 候选与裁判隔离；普通分片协作不承担盲评要求 |

启动前先解决会阻塞所有执行者的共同前提，再确定独立工作、共享状态和最小拆分。同一功能的紧密耦合代码由一个任务所有者负责，由其按约定内部拆分；不在顶层机械地按文件数拆散相关修改。只有一个执行者最合适时保留单一所有者。

## 启动规格（有效指定优先）

优先级：**用户本次请求 > 项目配置 > 团队配置**；逐项取有效值，未指定的选项交给宿主决定。

- 规格选项包含模型、推理强度、Agent 类型、运行环境、前后台方式、并发和嵌套限制，以及宿主支持的其他资源选项。
- nimo 不注入固定模型档位、并发数量或默认嵌套深度；不把“宿主默认”一律解释成“继承父模型”。
- 指定值仍须满足宿主能力、权限和硬限制；无效或不可用时报告具体冲突。已允许回退的可采用宿主默认并说明；未允许回退的不能静默替换。
- 宿主不公开实际默认值时记录“使用宿主默认策略”，不编造实际模型或参数。

## 任务合同

每次委派都必须明确：

1. 子任务目标、已知事实和必要资料位置。
2. 文件、产物或调查范围，以及不得修改的保持项。
3. 相关项目约束、工程原则和当前授权，包含允许的外部操作。
4. 预期产物、证据、验证方法和完成条件。
5. 与其他执行者的依赖、共享资源及整合所有者。
6. 是否允许继续委派，以及已指定的预算或停止条件。

上下文优先提供必要摘要和可访问的文件引用；宿主不能访问引用时提供经过筛选的内容，不假设工作区或会话天然共享。合同缺少影响执行的关键事实时先补齐；不能只发送“帮我实现”就启动。合同中的只读或范围限制是工程要求，只有宿主提供对应隔离时才构成技术强制限制。

## 嵌套与执行跟踪

- 普通执行者不自行扩展委派树；任务合同明确指定其作为复杂子任务所有者并允许继续拆分时，才可在分配范围内启动下级任务。允许委派不等于增加授权、预算或并发额度。
- 宿主不允许嵌套时，由上层协调者在允许范围内启动同级任务，或串行完成；不能让任务停留在等待一个无权启动的下级 Agent。
- 主 Agent 记录子任务标识、父任务、责任范围、产物位置和当前结果。记录属于会话或检查点，不另建任务数据库。
- 范围发生实质变化或旧上下文不再可靠时，用重新汇总的合同启动新任务，避免指令逐轮丢失。

## 结果验收

- 运行状态与验收结果分开：子任务运行结束进入**待验收**；父 Agent 核对产物、范围、证据和实际差异后**接受**或**退回**修正。
- 整体交付必须等所有必需子任务被接受，并完成**整合后的适用验证**；子任务各自通过不表示合并后的产物已通过。
- 必需分片失败时，在授权范围内修正、重新委派或由主 Agent 补做；无法补齐则报告阻塞，不误报整体完成。
- 候选任务失败时可比较剩余候选，但必须记录退出及比较范围缩小；不再满足预定比较要求时，不能宣称比较完整。

## 失败、超时与停止

- 超时先核实旧任务是否仍运行、产物是否已写入，再决定重启。
- 同一写入目标在旧任务停止状态未知时，不得交给新的执行者；可隔离的新尝试须明确最终整合所有者。
- 重试仍服从本次停止条件，不自动无限重启。
- 暂停和取消沿委派关系传递，并停止新任务启动。无法确认停止的下级任务及可能的外部副作用必须列出。
- 共享界面由一个操作者驱动，其他 Agent 可调查源码或审阅证据。
- 宿主不支持中断、隔离或后台运行时按实际能力报告，不能把期望当作执行结果。

## 宿主调用约定

- 用宿主原生的子 Agent 机制启动执行者，一次调用对应一个子任务；不建独立调度器。
- 任务合同内容填入子 Agent 的任务描述；启动规格逐项映射到宿主调用参数，nimo 不添加宿主未要求的固定参数；部分指定只覆盖相应选项，其余使用宿主默认。
- 子 Agent 返回后，主 Agent 读取其产物位置与证据，按「结果验收」处理；子 Agent 不直接写主任务的检查点。
- 各宿主的具体调用示例见 `integrations/<宿主>/`；示例中未经实跑验证的路径标注未验证。
