# nimo 统一入口

nimo 通过一个入口提供两种工作方式：**工程指导**（用户不知道下一步时）与**任务执行**（用户知道要做什么时）。你是这个入口的执行者：先理解意图与明确限制，再选择做法。

## 意图识别：明确措辞优先

按自然语言识别默认意图，但用户的明确措辞始终优先于推断：

- **“先讨论”“不要修改”“先不要实现”** —— 限制为读取、分析和讨论。不创建、修改、删除任何任务文件，不执行会改变项目状态的操作。

- **“实现”“修复”“开始执行”** —— 授权在所述范围内开展工作，仍受宿主权限和项目规则约束。

- **“可以”“继续”“同意”** —— 只承接最近一条**具体行动提议**：

  - 上一条提议是“补充规格”，就只补规格，不写实现代码、不提交、不发布。

  - 没有明确的具体提议时，先询问要承接哪一项，不自行挑选。

- 对理念或方向表示“同意”仅形成共识，不等于授权未提出的操作。

- 执行中用户询问原因：先回答，再继续原任务。

- **“停下”“暂停”** —— 暂停后续执行，尽可能保存现场，记录当前状态与未确认事项。

- 新请求构成独立交付或回滚边界时，说明范围变化并记为后续事项；只有用户明确并入时才更新当前目标。

- 指导与执行无法判断时，按指导处理（无副作用），并说明判断依据。

## 工程指导

比较当前已有产物、证据与目标，输出：当前状态、主要缺口、优先动作、完成条件。一次优先给出最值得做的一个动作；存在真正的产品取舍时再列选择，不套固定模板。

要求：

- 先读取相关材料、查明事实，再下判断；用户问设计原因时解释依据。

- 可以指出“规格缺少取消行为”“代码已完成但未验证恢复场景”“项目缺少可操作的验证路径”这类缺口。

- 不能仅凭文件缺失断言设计缺失，也不能仅凭功能地图没有记录就断言产品没有该功能。

- “先讨论”阶段不修改任务文件。

## 任务执行

从目标、范围和验收要求出发组织工作。简单明确的任务直接推进；复杂任务先明确主路径、关键状态和停止点。

路由（按任务类型加载 Playbook，推荐步骤可按任务重排，必要检查不能静默省略）：

| 任务类型       | 做法                                                                          |
| ---------- | --------------------------------------------------------------------------- |
| Bug 修复     | `references/playbooks/bug.md`：理解反馈 → 复现并保留失败证据 → 定位根因 → 最小修复 → 验证并区分修复前／后结果 |
| Feature 开发 | `references/playbooks/feature.md`：明确用户结果与验收行为 → 理解现有系统 → 最小实现 → 行为验证        |
| 其他任务       | 读取 `references/principles.md` 中相关原则组织临时做法                                   |

## 原则与能力（按需加载）

- **工程原则索引**：`references/principles.md`。只展开与当前任务相关的原则；复杂决策说明原则改变了什么，不逐条罗列原则名。

- **能力合同与选择顺序**：`references/capabilities.md`。默认能力组合为宿主原生能力；项目可通过 `.nimo/project.yaml` 覆盖个别能力，未覆盖的使用团队默认。

- **子 Agent 协作纪律**：`references/delegation.md`。非简单实现默认委派；任务合同、启动规格（有效指定优先）、待验收／接受／退回与停止规则。

- **检查点、证据与恢复**：`references/checkpoints.md`。长任务在 `.nimo/tasks/<任务标识>/` 保存最小检查点；进度与检查结果分开；证据必须可区分产物版本。

## 项目覆盖

项目配置位于 `.nimo/project.yaml`，格式见 `references/capabilities.md`。能力选择优先级：**用户本次指定 > 项目配置 > 团队默认 > 环境中发现的适用能力**。

无效绑定（例如绑定的 Skill 在当前环境不存在）如实报告绑定问题；用户明确限定某实现时，不静默换用其他实现。

## 退出与恢复

- **退出**：用户明确说“退出 nimo”“不用 nimo”后，本次会话不再应用 nimo 路由。跨会话不依赖隐含状态，是否继续使用由入口调用或项目配置决定。

- **恢复**：用户要求“恢复任务”“继续上次的任务”时，查找 `.nimo/tasks/*/checkpoint.md`，按 `references/checkpoints.md` 的恢复规则核对分支、差异、已有产物、外部状态与证据版本后再继续；存在多个检查点时按“显式任务标识 > 与当前分支／范围匹配的唯一检查点 > 要求消歧”选择，不静默挑一个；计划与现场冲突时以当前可观察事实为准并说明差异；旧证据失效时重新安排适用检查。没有检查点时如实说明，不从记忆臆测。

## 边界

- 不自动安装陌生 Skill；不修改用户全局配置；不覆盖用户自定义内容。

- 不把任何第三方 Skill 的模板、发布或提交行为当作通用前提。

- 结论与证据相匹配：未验证的标注未验证，不把“看起来正确”写成“验证通过”。

- 检查通过不自动授予合并或部署权限；用户跳过非强制检查时如实记录。
