# 把反复纠正变成不可能再犯

操作者在本仓库反复纠正 agent 犯同样的错误。改变仓库，让下一个 agent 犯不出来。

假设每个贡献者都是 agent：只看自己打开过的文件，复制离它最近的示例，走最短能编译的路径。把仓库设计成从一个文件看是对的改动，对整个仓库也是对的。

## 找出错误类别

先读近期提交、revert、评审意见、agent 指令文件和解释 workaround 的注释，把错误归类。同一类发生两次才算一类。

## 按可行的最高层级修复每一类

1. **用架构消除。** 每份状态一个 owner，每类任务一种受支持的做法。隐藏内部实现，让错误的 import 编译不过。把手同步清单换成单一事实来源。删掉 agent 会复制的旧做法和死代码。
2. **用类型强制，让坏状态写不出来。** 坏代码仍能编译时，加 lint 或 CI 检查，报错信息直接点名该用的文件、类型或函数。模式已经普遍时，只拦新增。
3. **用测试覆盖行为。** 修复或删除那些"它调用的每个函数都返回空也照样通过"的测试。
4. **文档和 agent 规则放最后，只写判断类问题。** agent 跳过它们时没有任何东西失败。

## 修复并证明

现在就修复最高频的几类，一类一次提交。证明每个新检查在真实历史错误上会失败。同一条命令本地和 CI 都跑。例外写在违规行上，带原因、失效日期和人工批准。

## 维护规则表

最后在 agent 指令文件里维护一张"规则 → 由什么强制执行"的表。操作者纠正你时：修掉错误，补上规则。规则已存在却没有东西强制执行，就是一次重复，在同一次变更里按最高层级修掉它。某类错误不可能再发生时，删掉对应规则。

回复：每一类错误、它的证据、选择的层级，以及更高层级为什么不成立。

与 [nimo-principle-encode-lessons-in-structure](../nimo-principle-encode-lessons-in-structure/SKILL.md) 的分工：那条原则是内核（把重复指令编码为机制），本技能是操作面（挖历史、分层修复、维护规则表）。

## 边界与交付

遵守 [宿主合同](../nimo-mode/references/host-contract.md) 和 [委派纪律](../nimo-mode/references/delegation.md)。只读、方案或停止要求优先，步骤不扩大授权。交付具体产物、当前版本证据、未完成项及原因。跳过步骤必须记录理由，不能用 Skill 名称列表代替成果。
