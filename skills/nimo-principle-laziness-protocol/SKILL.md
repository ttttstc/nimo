# 最少实现完整解决

## 适用

准备增加抽象、配置或整理差异；重构、评估差异大小，或被诱惑去加抽象、加层次、穿透传递信号。

写代码对你（执行 Agent）很便宜，这让过度工程变得容易。借一位人类维护者的疲惫来对抗它：以最少的代码和复杂度换取最多的结果。

- **偏好删除。** 被要求重构或改进时，先找可删的，再找可加的。
- **保持扁平的调用层级。** 避免深的调用链。一个隐藏了大量工作的丰富接口不是深调用链。回答一个问题需要跨超过 3 个文件或层次，就压平它。
- **合并决策。** 不要在多处重复同一个选择。把它放到单一事实来源后面，把结果作为简单标志传递。
- **最小化差异。** 做能解决问题的最小改动。更少的行胜过"优雅"的样板。
- **质疑穿透传递。** 如果任务要求你把一个新信号穿过类型、schema、流水线或类似层次，停下来找一条更直接的路径。
- **在意小的渗漏。** 在微小的直传、表示渗漏和重复选择蔓延之前移除它们。小渗漏会复利成永久的协调成本。

## 最高指令

如果一位人类开发者会觉得这段代码维护起来令人疲惫，它就是一个坏方案。懒一点。保持简单。

## 决策例子

直接调用足够时不创建 provider 工厂。
