# 展示你的工作

对于人事后审查的工作，决策轨迹让人能重建"决定了什么、为什么、依据什么证据"，而不必重跑工作或读完整个会话记录。保持一份规范日志：轨迹因此一致，未来的 Agent 也能找到它。

## 格式

单个 TSV 文件，每个决定一行。选 TSV 是因为代码托管平台把它渲染成可排序表格、`column -s$'\t' -t` 和电子表格都能读、一行只用一条追加命令就写进去。单元格保持单行。证据是指针，不是散文。

复制 [references/decision-log-template.tsv](references/decision-log-template.tsv)（表头行）开始一份干净日志。各列：

- **time.** ISO8601 时间戳，时间轴。
- **phase.** 阶段或工作流。
- **decision.** 选择或做了什么，一行。
- **reason.** 用平实的话说理由。如果是某个原则驱动的，直说（"先比较了选项，这是单向门"），不写成行话标签。
- **evidence.** 能证明它的链接或路径：commit SHA、PR 编号、`file:line`，或工件、trace、截图的路径。绝不是一段话。
- **result.** 结果或谓词状态：`tests green`、`reverted`、`pixel-diff 0`、`INCONCLUSIVE`、`open`。

一个例子，写得平实，让审查者一眼能读。只是示意，不要把这些行抄进真实日志。

```
time	phase	decision	reason	evidence	result
2026-05-24T09:02:00Z	frame	开工前先数了工作量，约 100 个组件、粗略 75 小时	想在长跑开始前知道体量	commit 3a9f1c2	开工前发现 5 件要先理清的事
2026-05-24T09:40:00Z	harness	改任何东西之前先给旧版本截了图	这样能新旧对比，抓住任何视觉变化	scripts/snapshot.sh, baseline/	保存了 120 张参照截图
2026-05-24T11:15:00Z	widget	把组件样式原样搬过去，不改观感	改动要小，结果要不变	commit 7c21e0a, pixel-diff 0	看起来一致，测试通过
2026-05-24T12:30:00Z	widget	扔掉了一个被委派者的工作，因为它的截图是空白的	查了真实文件，而不是信它的总结	worktree reset	已撤销；下次把委派指令收紧
```

## 记一行

每条记录按"你会怎么跟队友讲你做了什么"来写。平实的词、具体的动作，没有 AI 腔和抽象行话（[nimo-unslop](../nimo-unslop/SKILL.md) 对日志文本同样适用）。审查者不需要解码就能读懂每一行。

用本地工具 [nimo-mode/scripts/log.mjs](../nimo-mode/scripts/log.mjs) 保持行的格式正确：以 `--input <request.json>` 传入请求，字段为 `file`（日志文件的绝对路径）、`phase`、`decision`、`reason`、`evidence`、`result`；`time` 缺省取当前时间。工具会打 `time` 时间戳、首次写入时写表头、剥离混入单元格的制表符和换行，并把以 `=`、`+`、`-`、`@` 开头的单元格加上单引号前缀——审查者用电子表格打开日志时，来源不可控的内容（PR 标题、文件名、生成的文本）不会触发表格公式执行。工具同时拒绝写入符号链接路径，并在写入期间加锁。直接追加一行也可以，但单元格内容来自生成文本或用户提供文本时，注意同样的字节。

只记决策点和检查点，不是每个动作：选了哪个岔路、一个单元完成及其验证结果、一次转向或撤销及其触发原因、一个浮出的阻塞、一次门禁修复。循环式运行每轮迭代一行。跳过琐碎和自明的。

## 放在哪

默认日志是工作工件，不提交。放在工作目录的 `decisions.tsv`，或多个任务并行时放 `.audit/<task-slug>.tsv`，不纳入 git。大多数工作不需要提交的轨迹；本地日志照样让运行保持诚实，事后可以丢弃。

仅当工作大到审查者需要靠轨迹才能信任结果时才提交：大型跨语言移植、数周级迁移、任何信心必须被展示而不是被假设的工作。提交的日志在 PR 里渲染成表格。提交与上传按当前授权边界执行；此前筛除个人路径、凭据和无关数据，不写内部推理全文。

## 规则

- 一行是一个决定或检查点。一行放不下，说明决定还不够干脆。
- 只追加。错误的决定用新的一行取代，绝不编辑或删除历史。
- 优先用已提交脚本产出的证据，而不是手工一次性产物，让审查者能复跑（nimo-principle-encode-lessons-in-structure 原则 Skill）。

## 对照运行轨迹审计日志

运行结束、交回之前，检查日志说的是实话。读本宿主为本次运行保留的会话记录（路径由宿主或系统提示给出；宿主不提供会话记录时，对照本次任务的实际产物和你的工作记录审计，并如实记录这个缺口）。不要跨项目或跨工作区读取无关的私人会话。拿着日志对照实际发生的事走一遍：

- 每一行都对应真实发生的动作。删掉编造的或愿望式的条目。
- 每一行的证据可解析，且显示该行声称的内容。
- 塑造了这项工作却没记进日志的岔路、转向或被放弃的思路，是缺口。补上。
- 去掉凑数的行。没有人会去审计的行，不配占一个位置。

修日志，不修故事。如果工作偏离了某一行声称的内容，错的是那一行。

## 轨迹的独立审查

交回之前，用宿主提供的独立子 Agent 或独立上下文对轨迹做一次审查，优先从用户配置的模型里选与做事者不同模型家族的一个。自我审查不能替代它；要点是你自己带不来的新鲜眼睛。宿主无法提供独立上下文时，按[委派纪律](../nimo-mode/references/delegation.md)降级：不谎称做过独立审查，把这个缺口如实写进交付。审查者读审计轨迹和本次运行的会话记录，标记用户应当注意什么。不是重做工作，而是扫描哪里欠优或冒险：

- 记了决定，证据却弱或缺失。
- 验证步骤被跳过，或在会话记录里没有凭据地宣称通过。
- 事后看来冒险的选择（过早、范围蔓延、给症状打补丁）。
- 用户随手翻一翻会漏掉的缺口。

产生了轨迹的运行，每次回复以"注意"一节收尾。首行单独写审查所用的模型（`reviewed by <模型名>`），然后逐条列出标记，指向具体的行或时刻。"无标记"是合法取值；模型名不是。自查问的是日志是否说了实话；这一节问的是即使说了实话，用户还应该重点审视什么。

## 审读轨迹

从上往下读，跟随证据指针，抽查。代码托管平台把提交的 TSV 渲染成表格；终端里 `column -s$'\t' -t decisions.tsv` 一类命令可直接渲染。一行的证据解析不了，或结果未验证，就是审计抓住了缺口。

## 组合本 Skill

其他 Skill 把审计轨迹路由到这里，而不是各自发明一套。按名字引用本 Skill，由它拥有格式；不要复述列定义。

## 边界与交付

遵守 [宿主合同](../nimo-mode/references/host-contract.md) 和 [委派纪律](../nimo-mode/references/delegation.md)。只读、方案或停止要求优先，步骤不扩大授权。交付具体产物、当前版本证据、未完成项及原因。跳过保留理由，不能用 Skill 名称列表代替成果。
