# Notes 验证地图

本目录是验证 Notes 用户面行为的受维护事实源。驱动应用前先读本索引，然后把对应的功能文件当配方用。

## 基线前置条件

- 在 `http://127.0.0.1:4173` 用一次性数据目录启动 Notes。
- 设置 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`，让并发运行不共享状态。
- 播种标题为 `Quarterly plan` 与 `Grocery list` 的笔记。
- 把 `control-notes` 和 `notes` CLI 放上 `PATH`。
- 运行 `control-notes doctor` 并要求出现预期的 URL、数据目录和构建修订号。
- 绝不驱动不是本次验证运行启动的实例。

## 驱动约定

- 除非配方的首置条件另有说明，每条配方都从基线状态开始。
- 优先 ARIA 角色和可访问名称，而非 CSS 选择器或 DOM 位置。
- 每条命令按字面执行。引号内的名称与标志保持不变。
- 浏览器动作通过 `control-notes browser` 执行。
- 终端动作通过 `control-notes cli -- <command>` 执行。
- 变更之后恢复种子数据。清理时不移除证明产物。

## 证明与跳过报告

- 捕获用户动作和结果状态，不只最终画面。
- UI 证明包含 ARIA 快照和一张应用标识可见的截图。
- CLI 证明包含命令、stdout、stderr 和退出码。
- 变更证明包含对已存储值的只读第二视图。
- 每份产物都记录所用功能 ID 和入口。
- 不可达路径的报告附上尝试过的命令和未满足的前置条件。
- 不把一个被跳过的入口报告成经由另一条路径验证通过。

## 功能条目契约

每个功能文件以 H1 标题和一段用户可见行为的描述开始，随后按固定顺序使用恰好四个 H2。

1. `子功能` 列出短 ID，每个行为一行。
2. `用户视角入口` 列出每个用户入口。
3. `用 <harness> 驱动` 以 `前置条件：` 开头，用带标签的条目把每个用户动作、精确命令和可观察结果配对。
4. `陷阱` 列出会浪费或毁掉一次验证运行的坑。

实现细节不进地图。只写用户路径、稳定句柄、必要状态、命令和可观察证明。

## 功能

- [创建笔记](./create-note.md) 覆盖浏览器与 CLI 创建、取消、持久化和清理。
- [搜索笔记](./search.md) 覆盖工具栏、键盘与 CLI 搜索，含匹配、空结果和清除状态。
