# 打开编辑器

用户打开编辑器后可以继续编辑已有草稿，初始化完成后输入仍然保留。

## 子功能

- 新文档首次输入。
- 恢复已有草稿并继续输入。

## 用户视角入口

访问 `/editor`，使用编辑区域输入。示例假定该路由已在项目中核实。

## 用 Playwright 驱动

前置条件：用户已明确要求为编辑器补性能用例，只授权测试资产建设；示例约定冷启动可输入 p75 不超过 1000 ms。该数值不是 nimo 默认预算。

- **功能检查**：分别准备无草稿和含中文的已有草稿状态。通过真实输入事件继续输入，等待框架接管，再从界面与持久化第二视图读回；不丢字、不覆盖原草稿。具体选择器、准备方式与命令由项目资产填写。
- **性能场景 PERF-EDITOR-01**：从导航开始，到输入被接收。随后检查框架接管与保存结果；若后续丢字，整个样本失败，不能保留较早的“可输入”时间作为成功样本。预览可用另列指标，不与输入终点混用。
- **负载与环境**：固定草稿内容、浏览器与应用构建版本、视口、网络档；每次创建独立浏览器上下文，记录服务端仍为热实例，不宣称全链路冷启动。两个草稿状态分别统计。
- **采样**：先用不变版本探查噪声，再固定重复次数、p75 计算方式和失败规则。示例草案从 10 次探查起步，不据此宣称 p95 稳定。超时、输入错误和保存失败保留在原始结果中，不从报告抹去。
- **执行资产**：复用项目已有 Playwright 驱动；Create 生成并核实确切命令后交给 `nimo-verify`。命令尚未实现时，条目为未验证，不能将本示例路径伪装成可执行资产。
- **新项目基线**：首个可运行版本只报告实测分布与预算是否满足，不报告提速百分比。若超预算，交付失败证据，不自动修改编辑器实现。
- **修复后对照**：仅在另获性能修复授权后，按 AB、BA 顺序在同一时段交替测两个隔离版本。冻结用例、数据与环境，比较耗时，同时要求功能护栏通过。
- **证据与阈值**：记录产物版本及工作区差异、协议版本、每个原始样本、错误、成功数、trace 和草稿读回结果。阈值检查只读；协议变化时重新校准，不能把测得的慢值写成新上限。

## 陷阱

- 元素可见、包含预存文字，不足以证明新输入可用；输入检查必须区分原内容与本次操作。
- 新上下文会清理浏览器状态，已有草稿需要按真实存储方式单独准备；不能把该场景意外测成新用户。
- 把重活延后到预览、保存或第一次导出，不代表这些操作也变快了；根据影响范围保留对应功能回归。
- 一次性能失败只触发发现报告。进入 `perf-issue` 或 `hillclimb` 需要相应优化授权。
