# Notion 文档

## 这个来源包含什么

- PRD（产品需求文档）
- 技术规格与 RFC
- 架构决策记录（ADR）
- 设计评审的会议纪要
- 带领域上下文的团队页面
- 事故复盘
- 可能解释防御性代码的 runbook
- 设定优先级的战略文档

Notion 是"为什么"在变成代码之前以长篇形式存在的地方。一个重要的功能通常有一篇文档。

## 怎么搜

使用 Notion 连接器（工具名以 Notion MCP 为例）。

1. **用 `notion-search` 做关键词搜索。** 试：
   - 功能名
   - 目标代码的关键符号 / 类名
   - 作者账号（设计文档常在代码落地前写成）
   - 错误串或用户可见术语
   - 知道代码上线时间时，做时间限定的查询
2. **用 `notion-fetch` 拉取候选页面。** 读完整内容，不是预览；动机经常埋在文档中段。
3. **跟随反向链接与子页面。** 设计文档常有"考虑过的备选方案"附录或实现笔记的子页面。
4. **查相关数据库。** `notion-query-data-sources` 和 `notion-query-meeting-notes` 能浮出讨论过该决策的会议纪要。
5. **搜作者的个人空间。** PR 作者有个人笔记本（一些公司常见）时，里面可能有先于代码的探索性思考。

## 这里的好证据长什么样

- 一篇"问题陈述"或"动机"小节与目标代码用途吻合的 PRD
- 一个"考虑过的备选方案"或"被拒绝的方案"小节
- 一篇把目标代码点名为某次事故修复的复盘
- 记录了"我们定了 X 因为 Y"、且与 PR 的作者/日期范围对上的会议纪要
- 一份非平凡填写过的 ADR 模板（状态、背景、决策、后果）

## 常见坑

- **过时文档。** 规格常在实现前写就、之后不更新；文档描述的可能是变过的计划。与实际 PR 交叉核对。
- **文档与现实漂移。** 规格说"我们会做 X"而代码实际做 Y。标记分歧；汇总者会呈现这个矛盾。
- **模板话。** 有些组织要求的 "Why" 小节填的是废话。找具体性。
- **无链接的文档。** 最相关的文档可能没有被任何地方链接。宽泛的关键词搜索有帮助。
- **多份草稿。** 同一主题有多篇文档时，找定稿的或最近更新的那篇。查日期。
- **访问受限页面。** 无权访问的页面记为缺口。

## 返回什么

每篇相关文档：
- 标题与 URL
- 作者与最后更新日期
- 动机文本（逐字引文），带页面/小节位置
- 相关的链接页面（让汇总者可以引用）
- 文档是定稿还是草稿
