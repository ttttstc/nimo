# Datadog 遥测

## 这个来源包含什么

Datadog 持有运行时记录：生产里实际发生了什么——与计划或讨论相对。

- **指标。** 团队埋点的 counter、gauge、histogram。一个指标的*存在*本身就是证据：有人认为这个数值得盯。
- **监控器与告警。** 团队认为值得半夜叫醒人的条件。一个在 `rate_limit_hit > 10/min` 上触发的监控器，是团队担心该阈值的直接证据。
- **仪表盘。** 策展视图。图表告诉你团队认为一个子系统什么重要。
- **APM trace 与 span。** 请求级运行时数据。对"这里为什么慢""这里为什么有超时"有用。
- **日志。** 高容量事件记录。经常含有促成防御性代码的错误条件。
- **事故。** 带时间线与关联复盘的正式事故记录。
- **notebook。** 探索性调查；经常含假设与分析。

Datadog 回答"这段代码写就前后，生产的现实是什么？"——这经常解释代码的形状。

## 怎么搜

使用 Datadog 连接器（工具名以 Datadog MCP 为例）。先宽后窄。

1. **识别归属服务。**

   ```
   search_datadog_services (按名称或团队过滤)
   search_datadog_service_dependencies (看上游/下游)
   ```

2. **先看仪表盘与监控器。它们告诉你团队在意什么。**

   ```
   search_datadog_dashboards (查询：功能名、服务名、符号)
   search_datadog_monitors   (同样的查询)
   ```

   仪表盘或监控器覆盖目标时，记下它的查询与所盯的阈值。阈值经常就是"为什么这里钳在 N"的答案。

3. **目标周围的指标。**

   ```
   search_datadog_metrics (按名称模式，如功能名或符号)
   get_datadog_metric_context (元数据：描述、单位、标签)
   get_datadog_metric (时间序列；"PR 日期前后有尖峰吗？")
   ```

   把指标轨迹与目标的加入/变更日期关联起来是强支撑证据："`payment_timeout` 指标 2023-11-03 尖峰，重试逻辑 2023-11-06 合并。"

4. **日志。收窄，不要倾倒。**

   ```
   search_datadog_logs (目标附近的原始日志模式，设 use_log_patterns=true)
   analyze_datadog_logs (SQL 风格聚合，只在需要计数时用)
   ```

   用符号、错误串或功能名搜索。**强烈优先限定时间的查询**（如变更前后各 30 天）。日志量巨大；无约束搜索浪费时间且可能超时。

5. **APM span 与 trace。**

   ```
   aggregate_spans    (统计："这个端点多久失败一次？")
   search_datadog_spans (检视单个 span)
   get_datadog_trace  (某个具体的 trace ID)
   ```

   对超时、重试、慢路径、跨服务行为有用。

6. **事故。**

   ```
   search_datadog_incidents (按标题、团队、日期范围)
   get_datadog_incident     (某次事故的完整细节)
   ```

   目标看起来是防御性的，就在它加入的时间前后搜事故。时间线里带"为 X 加了防御检查"的事故，接近直接证据。

## 这里的好证据长什么样

- 监控器的查询与阈值和代码强制执行的约束吻合（代码钳到 100；监控器在请求超过 100/min 时告警）
- 目标作者创建的仪表盘，其组件与代码度量或防护的东西对应
- 一条指标在代码合并前立刻尖峰、之后数值稳定
- 引用目标代码、相同符号或相同错误串的事故记录
- 日志显示防御代码会阻止的特定错误模式，时间戳在变更前的窗口内

## 常见坑

- **相关不是因果。** PR 前尖峰、PR 后平稳是有提示性的，不是决定性的。同窗口可能落了其他变更。查邻近 PR。
- **对你找到的图过拟合。** Datadog 可视化是人*做*出来的，反映那个人的框架。一张名为"重试成功率"的图是团队在意重试成功率的证据，不是某行代码存在的原因。
- **消失的遥测。** 指标可能被重命名、删除或保留期很短。相关窗口的数据找不到时，那是缺口，不是空结果。
- **规模下的噪音。** 用常见字符串搜日志会返回上千条匹配。激进地按服务、标签、时间收窄。用 `analyze_datadog_logs` 聚合，而不是倾倒原始日志。
- **有埋点不等于有因果。** 指标的存在只说明有人在意到要度量它，不代表代码*因为*它而加。与提交/PR 日期交叉核对。

## 返回什么

每条相关条目：
- 类型（仪表盘 / 监控器 / 指标 / 日志模式 / trace / 事故 / notebook）
- 标题或名称
- 链接或标识（仪表盘 ID、监控器 ID、指标名、事故 ID）
- 属主/作者与创建/修改日期
- 与问题相关的具体条件、查询或引文（尽量逐字）
- 相关性：它对目标代码暗示什么，连接有多强
