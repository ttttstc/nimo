# Slack 对话

## 这个来源包含什么

- 对问题与决策的实时讨论
- 做出紧急决策的事故频道
- 辩论过权衡的设计讨论串
- 资深工程师回答的、没进文档的问题
- 解释某东西为何被重访的合并后讨论
- 私信（通常不可搜索，相应缩小范围）

Slack 经常是*真正*的决策发生的地方，尤其是不值得写文档的小改动。它也是最易逝的来源：讨论串被删、频道被归档、搜索质量随时间劣化。

## 怎么搜

宿主提供的 Slack 连接器形态各异。先确认当前可用的是哪个 Slack 连接器，检查它的工具形态与查询词汇；连接器需要认证而认证失败时，停下并报告缺口。只搜索用户授权的工作区与频道。

1. **按作者限定搜索。** PR 作者在 PR 合并日期前后的消息。范围骤减，且经常命中金矿。
2. **功能名与关键符号的关键词搜索。** 包括错拼与随口的措辞。
3. **PR URL 搜索。** Slack 在评审或讨论 PR 时常贴链接。搜索 PR URL（或只搜 `/pull/<number>`）。
4. **错误串搜索。** 代码处理某个具体错误时，搜索该错误串。事故讨论串经常浮出来。
5. **限定频道的搜索。** 收窄到可能的频道：
   - `#eng-*`。工程讨论
   - `#proj-*`。项目频道
   - `#incident-*` / `#sev-*`。事故频道
   - 归属团队自己的频道
   - 设计评审频道
6. **讨论串遍历。** 找到相关消息时，拉取整条串。决策常在回复里。

## 这里的好证据长什么样

- 一条显式辩论过权衡的讨论串（"我本打算用 A，但 B 更好，因为……"）
- 一条描述了代码所防 bug 的事故频道消息
- 评审者的问题 + 作者或负责人的权威回答
- 提到某次会上做了决策的引用
- 产品经理或客户侧工程师解释客户诉求的消息

## 常见坑

- **频道考古的极限。** 保留策略可能已删除很老的消息。某个日期之前什么都找不到时，标注保留期断崖。
- **搜不到的私信。** 很多决策发生在搜不到的私信里。你会漏掉它们；这是已知限制。
- **把玩笑当"决策"。** Slack 很随意。"哈哈就那么干吧"不是决策，即使它先于提交。找有考量的讨论。
- **单条消息的语境塌缩。** 没有串，单条消息读起来常与上下文中不同。永远拉整条串。
- **认证失败。** 连接器未认证时，停下。不要编造发现。报告 Slack 不可搜索。

## 返回什么

每条相关讨论串：
- 频道名
- 永久链接或讨论串 ID
- 参与者
- 讨论的日期范围
- 关键引文（逐字）与归属
- 语境：它属于什么讨论串/事故/讨论
