# 把工作排成可验证的单元

把工作排成小单元的序列，每个单元收尾于一个可检查的状态；当前单元没有变绿，不前进。同一条纪律在两个高度上运行：怎么执行，怎么交付。

## 适用

多步工作：清扫、迁移、批量同类编辑、多文件任务，以及提交与 PR 的堆叠顺序。

## 为什么存在

在引入破坏的那个单元上就地抓住破坏，定位是便宜的。一批做完才发现的破坏是被埋起来的，而且你已经在坏掉的基础上继续盖了楼。把同样的单元排成审查者可重放的交付序列，就把"相信我"变成了"看着它先变红、再变绿"。

## 执行

在清扫、迁移或任何批量同类编辑中，验证完每一个变更，再开始下一个。绝不把编辑攒成一批、最后验证一次。每个单元是一对前后括号：已知良好状态、一个变更、跑检查、然后继续。先变基到干净的主干上，让每次检查都对着真实基线。当杠杆工具替你执行编辑时，逐单元检查几乎免费——也要跑。

## 交付

提交和 PR 按能证明工作的顺序堆叠。标准形状是先落失败测试，修复叠在它上面。第一个单元证明 bug 真实存在（红），下一个证明它被解决（绿），审查者同时看到问题与证明。其他叙事顺序同理：重塑之前先做减法、处理之前先取基线、功能之前先搭脚手架。每个提交独立成立，整个序列读起来像一个论证。

## 模式

- 选以检查收尾的最小单元：一次编辑加它的测试，或一个独立成立的提交。
- 推进前验证。逐单元红到绿，绝不推迟到最后一批。
- 给单元排序，让序列自身就能建立信心：执行时给你自己，读堆栈时给审查者。

它是 [nimo-principle-prove-it-works](../nimo-principle-prove-it-works/SKILL.md)（保证每次检查都是真的）在排序面上的补充，与 [nimo-principle-build-the-lever](../nimo-principle-build-the-lever/SKILL.md)（让逐单元检查变得便宜）互补。

## 决策例子

配置路径检查通过，再接对话写入。

## 应用证据

读取本文件后，指出它改变的具体决定和产物。没有改变决定时不列为已应用。当前授权、宿主权限和项目强制门禁始终有效。
