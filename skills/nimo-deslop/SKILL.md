# 清理本次差异

清理不是可选的抛光。带着叙述注释和防御性死重的差异在审查者眼里是未完成品，而多余代码正是下一个 bug 藏身处。差异显得臃肿时，提交前就清理，不要等审查指出来。

分工：代码里的 slop 归本 Skill；说明文字的清理归 [nimo-unslop](../nimo-unslop/SKILL.md)；提交审查前的注释独立评审归 [nimo-no-comments](../nimo-no-comments/SKILL.md)。本 Skill 是作者侧自查，不替代独立评审。

## 步骤

1. 针对本次差异扫描下列模式，不扫全仓库。
2. 从目标逐项检查差异必要性，删除本次产生的：叙述性注释、无依据的防御性守卫、死兼容路径、无关改动、无用包装、重复、失效变量和多余配置。
3. 重写：优先标准库和既有机制，但不删用户要求的能力、边界校验或错误处理；保持行为不变，匹配项目既有风格。
4. 不顺手格式化无关代码，不删用户原有改动。
5. 自查："这个差异里还有哪些地方一眼就是顺手生成的凑数？"修掉剩下的痕迹。
6. 整理后复验受影响行为。

## 边界与交付

遵守 [宿主合同](../nimo-mode/references/host-contract.md) 和 [委派纪律](../nimo-mode/references/delegation.md)。只读、方案或停止要求优先，步骤不扩大授权。只清理本任务制造的问题。交付具体产物、当前版本证据、未完成项及原因。跳过保留理由，不能用 Skill 名称列表代替成果。
