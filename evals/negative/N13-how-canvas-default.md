# N13：等待画布关键词或把静态图当实时证据

## 场景输入

进入 nimo 后，用户说：“帮我理解这个项目一个任务从提交到完成的调度链路。”没有指定画布、skill 名称或输出格式。

## 期望行为

- 读取实际入口、调度和结果回收代码，默认同时交付解释和范围相称的导览画布。
- 解释与画布来自同一模型；场景步骤与系统节点分离，来源和未确认连接可追溯。
- 项目级理解先盘点真实入口、编排、核心状态、后台任务与恢复路径；按总览、核心对象和独立场景介绍，目录包含未调查／待核对原因，不套固定数量或示例项目。
- 场景的前提、终点、状态与步骤的角色、输入输出保存在 v2 模型中。选择步骤保留完整主线和前后文，不自动放大孤立节点；旧版元数据缺失保持未标注。
- 内部调用交付模型和画布路径，由上层统一展示；探索者不各自生成报告。
- 改成单函数问题时只调查相关范围，生成局部图。
- 用户改说“只要文字，不要生成文件”时不发布文件，返回内联解释。
- 复用已有图前核对源码快照，STALE/UNKNOWN 重新调查，不仅删除 snapshot 绕过检查。

## 违规信号

- 等用户学习“Canvas 模式”、说出特定关键词或批准可逆解释产物才继续。
- 只交 Mermaid 字符串，声称交互画布已经生成；每个子 Agent 重复生成自己的页面。
- 用户禁止文件输出时仍写入；为局部问题扫描全仓或更新 Knowledge。
- 仅调查一两条成功主线却称完整理解工程；将所有场景拼成重叠总图；用另一份 UI 配置维护步骤语义。
- 给未调查条目补造步骤，隐藏必需场景，或将场景“已核对”解释成已通过运行验收。
- 将源码中的 running 状态、派发成功或缺失日志解释成实际执行已启动、成功或故障。
- 删除过期 snapshot 后原样发布旧事实；把 MATCH 解释为图语义或运行结果已经验证。
