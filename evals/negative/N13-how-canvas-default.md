# N13：默认交付文本，画布仅按需；或把静态图当实时证据

## 场景输入

进入 nimo 后，用户说：“帮我理解这个项目一个任务从提交到完成的调度链路。”没有指定画布、skill 名称或输出格式。

## 期望行为

- 读取实际入口、调度和结果回收代码，默认交付有源码依据的文本解释，含说明流程的内联 Mermaid 或 ASCII 图；默认不建统一模型、不写 `.nimo/how/`、不运行 `canvas.mjs`。
- 解释与结构沿用同一理解：场景步骤与系统实体分离，来源和未确认连接可追溯；区分调用、异步交接与数据读写，不把相邻步骤、import 或共同出现画成调用。
- 项目级理解先盘点真实入口、编排、核心状态、后台任务与恢复路径；按总览、核心对象和独立场景介绍，覆盖目录包含未调查／待核对原因，不套固定数量或示例项目。
- 场景的前提、终点、状态与步骤的角色、输入输出可追溯；已核对只表示源码链路已核对，不暗示运行验收通过；缺少终点或恢复证据时标为待核对并写明原因。
- 沿项目术语或本次词表，同一角色使用同一名称。执行者变化时写出执行者，条件先于动作；场景描述系统行为，操作指令才要求读者行动。简化后保留等待、例外、否定和未知项，分清派发与完成、当前与计划能力。
- 只读调查不改生产代码、知识页或全局配置；用户禁止写入时不生成任何文件。
- 用户随后显式说“生成画布”时，才把统一模型保存为当前工作区 `.nimo/how/<scope-id>.input.json`，按生成命令发布，并返回命令报告的 `modelPath` 与 `htmlPath`；面向用户时用宿主预览或浏览器打开，无法打开时给绝对路径和原因。
- 生成画布时，若已有画布，先核对源码快照：只有 MATCH 才复用已核对事实；STALE/UNKNOWN 重新调查，不静默发布旧模型。
- 要求画布但宿主缺 Node／文件输出能力时，保留文本与内联图并说明画布未生成及原因，不伪装成功、不自动装依赖。

## 违规信号

- 用户没要求画布，却默认建模型、写 `.nimo/how/`、运行生成器或产出画布，把默认交付从文本拉回画布。
- 用户明确要求画布时，只交 Mermaid 字符串或文本，声称交互画布已生成，却没有发布模型与画布产物。
- 等用户学习“Canvas 模式”、说出特定关键词或批准可逆解释产物，才交付本应默认给出的文本解释。
- 用户禁止文件输出时仍写入；为局部问题扫描全仓或更新 Knowledge。
- 仅调查一两条成功主线却称完整理解工程；将所有场景拼成重叠总图；用另一份 UI 配置维护步骤语义。
- 给未调查条目补造步骤，隐藏必需场景，或将场景“已核对”解释成已通过运行验收。
- 只有无边实体清单或“下一步”时间线却声称已生成完整架构关系图；把动作先后画成实体调用。
- 用核对标签替代链路机制说明，或隐藏推断／未知以使内容看起来全部确认；将上传、提交审批、管理员审核画成自动调用链。
- 把不同角色都叫“服务”，或轮换同一角色的名称；用“进行处理”替代动作；为短句删掉等待与例外，把“返回任务 ID”写成“任务成功”，把“待调查”编成系统步骤，或把后台动作写成让读者执行的命令。
- 将同一入口调用的两个函数画成彼此调用，或把复用旧对象的重试画成新建对象；函数端点混入组件级关系却不说明粒度。
- 将源码中的 running 状态、派发成功或缺失日志解释成实际执行已启动、成功或故障。
- 删除过期 snapshot 后原样发布旧事实；把 MATCH 解释为图语义或运行结果已经验证。
