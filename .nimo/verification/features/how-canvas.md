# how 画布验收配方

执行前绑定当前 HEAD、工作树差异与模型源码快照；各场景的结果及证据另存 `.nimo/tasks/how-canvas/`。源码阅读、静态合同检查和实际浏览器结果分别记录。

| 场景 | 驱动与预期 | 证据 |
|---|---|---|
| AC01 默认交付 | 独立宿主 Agent 读取当前 how，接受未提到画布的项目理解问题；应交付解释和生成器报告的路径。局部问题生成局部图；内部调用不重复打开；只要文字时不写文件 | 原始问题、Agent 结果、真实产物或未写入事实 |
| AC02 场景导览 | 浏览器打开实际 CLI 产物，分别阅读总览、核心对象与分组场景。只显示所选场景完整主线，当前步及前后文清楚；前后导航、搜索、来源、拖动/缩放/Fit、hash 可用；切步骤不自动缩放，窄屏无页面横向溢出且详情靠近图。未调查／排除条目显示原因，无虚构步骤 | 操作断言、宽窄截图、console/page 错误 |
| AC03 图与文件边界 | `node --test tests/state/how-canvas.test.mjs`；涵盖 v1 兼容、v2 语义元数据、空步骤状态、合法图、局部图、不确定节点、重复或悬空引用、来源/输出越界、注入和失败保留旧产物 | CLI/函数断言及退出码 |
| AC04 复用检查 | 生成模型后运行 `--check`；修改或删除引用源应 STALE，缺少/不完整快照 UNKNOWN，未变化 MATCH，带过期快照不得静默重新发布 | 原始与修改后的独立读回、机器结果 |
| AC05 可移植与集成 | 单文件通过 `file://` 在浏览器打开且无网络/SDK依赖；`node tests/assets/check-package.mjs`、`npm --prefix skills/nimo-mode/scripts run check`、`node tests/run.mjs`、精确安装资产读回与 `git diff --check` | 工具输出与安装副本、环境和基线差异 |

UI 自动化使用可用浏览器工具或 Playwright；缺少真实浏览器时 AC02 保持 NOT_RUN，不能以 HTML 字符串断言通过。生成器和查看器的运行时源码是字段和操作的真源；模型要来自真实项目源码，验收不得用模拟成功状态替代链路依据。

原始自然请求：`帮我理解这个项目一个任务从提交到完成的完整调度链路，以及其他核心场景。` 该请求无需携带 skill 名称、画布关键词或输出标志。应由源码形成场景清单，覆盖前提、角色、输入输出、终点及未调查原因。进入 how 的宿主加载方式应与自动发现效果区分；本配方不声称修改仓库后已有全局安装会自动更新。
