# how 画布验收配方

执行前绑定当前 HEAD、工作树差异与模型源码快照；各场景的结果及证据另存 `.nimo/tasks/how-canvas/`。源码阅读、静态合同检查和实际浏览器结果分别记录。

| 场景 | 驱动与预期 | 证据 |
|---|---|---|
| AC01 默认交付 | 独立宿主 Agent 读取当前 how，接受未提到画布的项目理解问题；应交付解释和生成器报告的路径。局部问题生成局部图；内部调用不重复打开；只要文字时不写文件 | 原始问题、Agent 结果、真实产物或未写入事实 |
| AC02 场景导览 | 在宿主允许的浏览器入口打开实际 CLI 产物，先读核心答案和各块职责，再按用户问题进入场景。默认看完整编号步骤卡片、当前步真实交接与输入输出；实现实体图与源码按需展开。收起图时不创建隐藏相机，展开后平移、指针缩放、Fit、定位和关系检查可用。选择步骤只更新高亮，坐标及缩放稳定；目录、前后步、键盘和 hash 可用；窄屏无页面横向溢出。未调查／排除显示原因，零边／未关联连接明示缺口，不从动作顺序画调用 | 本次视频帧、实际操作断言、宽窄截图、console/page 错误 |
| AC03 图与文件边界 | `node --test tests/state/how-canvas.test.mjs tests/state/how-graph.test.mjs`；涵盖真实图投影与几何、v1 兼容、v2 语义元数据、空步骤状态、合法图、局部图、不确定节点、重复或悬空引用、来源/输出越界、注入和失败保留旧产物 | CLI/函数断言及退出码 |
| AC04 复用检查 | 生成模型后运行 `--check`；修改或删除引用源应 STALE，缺少/不完整快照 UNKNOWN，未变化 MATCH，带过期快照不得静默重新发布 | 原始与修改后的独立读回、机器结果 |
| AC05 可移植与集成 | 单文件无外部资源／宿主 SDK 依赖；浏览器具备文件入口时验证 file://，否则保留该入口未验事实，在用户提供或正常授权的 HTTP 应用入口验收。`node tests/assets/check-package.mjs`、`npm --prefix skills/nimo-mode/scripts run check`、`node tests/run.mjs`、精确安装资产读回与 `git diff --check` | 工具输出与安装副本、协议能力和未验边界 |
| AC06 L0 与 4+1 | 默认总览仅画显式运行组件，关系由真实跨组件实体边聚合，方向、类型、不确定性与原始边可追溯；主流程引用已有场景，不由编号补边。组件／关系能进入实际相关章节。业务职责、运行协作、源码组织、部署边界与场景各有阅读入口，部署区分代码配置与实际运行；旧模型缺少层级时提示缺口，不回退全实体密集图 | 组件归属与边投影断言、真实模型读回、允许入口的宽窄操作与截图 |
| AC07 简明讲解 | 独立上下文读取当前 Skill、探索与解释提示词及简明讲解规则，接受包含别名、两个执行角色、异步等待、失败分支及计划能力的理解任务。图文名称应一致，步骤写清执行者、条件、交接与结果；保留例外、否定和未知，区分派发与完成。无法辨别的别名保留歧义，不合并实体。未知项留在说明中，不能编成系统步骤。系统流程不能改成读者命令，不新增模型字段或连接。检查器命中逐项裁决，不以短句或零命中证明语义正确 | 原始任务、受检事实、实际解释与模型、独立裁决；构造示例仅证明讲解规则，不证明真实系统或 UI |

UI 自动化使用可用浏览器工具或 Playwright；缺少真实浏览器时 AC02 保持 NOT_RUN，不能以 HTML 字符串断言通过。生成器和查看器的运行时源码是字段和操作的真源；模型要来自真实项目源码，验收不得用模拟成功状态替代链路依据。

图布局相关回归覆盖跨区真边、环路、自环、平行连接与枢纽，断言节点／标签不覆盖、方向与端点正确。真实浏览器核对可见内容和镜头行为，不能以几何测试替代。安全策略拒绝的地址不得通过换浏览器、CDP 或间接提供同一被拒绝文档绕过；使用允许的正常应用入口，不能访问时保留未验证。

阅读重点验收：卡片说明实体作用，本步面板列实际来源到目标及调用／交接／读写内容，并说明执行者、输入输出与完成条件；常规已记录来源收在详情中，不反复显示核对标签，推断与缺口仍可见。场景内按首次动作关联安排阅读顺序，选择步骤不重排、不移动相机；编号先后不补调用边。上传、提交评审和审批若是独立 HTTP／人工动作，界面必须明确等待条件，不能画成上传后自动发布。对象查看可读上下游，实现依据可展开。

可读性验收：新人只读默认面板，应能说出系统用途、每块分工、一次操作的交接和等待终点，无需先解读函数名。标题使用用户问题；一个面板只回答一个问题，正文用短句与一致角色名。总览说明来自现有模型，不硬编码示例项目；全部场景及缺口仍可发现。旧 v1／缺少总览节／局部图有基于现有事实的回退。简图方向来自显式边，不因编号先后生成调用。可展开的实现图仍保留真实实体、源码依据和未知提示。

分层验收：细粒度实体只能明确归属一个 L0 组件，未知引用、重复归属和悬空场景引用必须拒绝；未归属成员显式记录缺口。L0 不从职责分区推测进程，不把内部函数边和数据表画进总览。4+1 各切面引用同一实体与场景事实，缺少源码／部署依据时显示未调查。紧凑布局不得因细节实体数量增多而增长，节点和连线点击使用组件名称而不是内部合成 ID；原有场景步骤、来源、定位和安全边界保留。

原始自然请求：`帮我理解这个项目一个任务从提交到完成的完整调度链路，以及其他核心场景。` 该请求无需携带 skill 名称、画布关键词或输出标志。应由源码形成场景清单，覆盖前提、角色、输入输出、终点及未调查原因。进入 how 的宿主加载方式应与自动发现效果区分；本配方不声称修改仓库后已有全局安装会自动更新。
